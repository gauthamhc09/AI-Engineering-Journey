# Module 00.7.09 — Recursion

## 1. What Is Recursion?

**Recursion** is a programming technique in which a function calls itself to solve a smaller version of the same problem.

A recursive solution usually has two essential parts:

1. **Base case:** A condition that stops the recursive calls.
2. **Recursive case:** A step that reduces the problem and calls the function again.

Without a base case, the calls may continue until Python raises a `RecursionError`.

## 2. A Simple Example: Countdown

```python
def countdown(n):
    if n == 0:                 # Base case
        print("Done!")
        return

    print(n)
    countdown(n - 1)           # Recursive case


countdown(3)
```

Output:

```text
3
2
1
Done!
```

Each call receives a smaller value. When `n` becomes zero, the base case stops further calls.

## 3. How Function Calls Work: The Call Stack

When a function is called, Python creates a **stack frame** that stores information needed for that call, such as local variables and where execution should resume.

Recursive calls create additional stack frames.

For `countdown(3)`, the calls build up like this:

```text
countdown(3)
  countdown(2)
    countdown(1)
      countdown(0)  <- base case
```

Once the base case returns, execution unwinds in reverse order:

```text
countdown(0) returns
countdown(1) returns
countdown(2) returns
countdown(3) returns
```

This is why deeply recursive functions consume call-stack space.

## 4. A Recursive Function That Returns a Value: Factorial

Factorial is defined as:

\[
n! = n \times (n-1) \times \cdots \times 1
\]

And:

\[
0! = 1
\]

Recursive implementation:

```python
def factorial(n):
    if n == 0:                 # Base case
        return 1

    return n * factorial(n - 1)


print(factorial(5))  # 120
```

Conceptually:

```text
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 5 * 4 * 3 * 2 * 1 * factorial(0)
= 5 * 4 * 3 * 2 * 1 * 1
= 120
```

The recursive calls first move toward the base case. The multiplication results are then computed as calls return.

For this implementation:
- Time complexity: O(n).
- Call-stack space: O(n).

A production-quality function should also validate that `n` is a non-negative integer.

## 5. Recursion vs Iteration

Iteration uses loops such as `for` and `while`. Recursion uses function calls.

Factorial with a loop:

```python
def factorial_iterative(n):
    result = 1

    for value in range(2, n + 1):
        result *= value

    return result
```

Factorial with recursion:

```python
def factorial_recursive(n):
    if n == 0:
        return 1

    return n * factorial_recursive(n - 1)
```

| Aspect | Recursion | Iteration |
|---|---|---|
| Mechanism | Function calls | Loops |
| State | Stored across call frames | Usually maintained in variables |
| Stack usage | Often grows with recursion depth | Usually O(1) extra space for a simple loop |
| Readability | Natural for self-similar problems | Often simpler for straightforward repetition |
| Risk | Deep calls can exceed recursion limit | Incorrect loop conditions can cause infinite loops |

Recursion is not automatically better or faster. Choose the form that makes the algorithm easiest to reason about while meeting performance and stack constraints.

## 6. Recursion and the Call Stack

Every active recursive call has its own local variables and execution position.

For example, in:

```python
def sum_to(n):
    if n == 0:
        return 0

    return n + sum_to(n - 1)
```

Each call must retain its own `n` while the smaller call runs. Those pending operations are represented by stack frames.

If recursion depth is proportional to `n`, stack space is O(n).

## 7. Recursion Trees

A recursion tree represents recursive calls as a tree:
- Each node represents one function call or subproblem.
- Its children represent recursive calls made by that subproblem.
- The tree helps analyse total work and call depth.

A linear recursive function such as `sum_to(n)` makes one smaller call at each step, producing a chain of depth O(n).

A divide-and-conquer algorithm may make two smaller calls at each level, producing a branching recursion tree.

## 8. Common Recursion Patterns

### A. Linear recursion

Each call makes one recursive call.

```python
def sum_to(n):
    if n == 0:
        return 0
    return n + sum_to(n - 1)
```

### B. Multiple recursion

A call makes more than one recursive call. A simple Fibonacci implementation is an example:

```python
def fibonacci(n):
    if n <= 1:
        return n

    return fibonacci(n - 1) + fibonacci(n - 2)
```

This implementation repeats many calculations. Its time complexity is exponential, commonly expressed as O(2^n) as an upper bound, and its call-stack depth is O(n).

### C. Divide-and-conquer recursion

A problem is divided into smaller subproblems, which are solved recursively. Merge Sort and Quick Sort use this general pattern.

## 9. Common Recursion Errors

1. **Missing base case:** Calls never reach a stopping condition.
2. **Base case is unreachable:** The recursive step moves away from the stopping condition.
3. **Problem does not get smaller:** Calls repeat the same input.
4. **Too much repeated work:** The same subproblem is recalculated many times, as in naive Fibonacci.
5. **Excessive depth:** The call stack grows beyond Python's recursion limit.

A reliable way to design a recursive function is to ask:
- What is the smallest input I can solve directly?
- How do I reduce a larger input toward that case?
- What result should each smaller call return?
- How are those returned results combined?

## 10. Python's Recursion Limit

Python limits recursion depth to protect the interpreter from unbounded call-stack growth. Deep recursion can raise `RecursionError`.

You can inspect the current limit:

```python
import sys

print(sys.getrecursionlimit())
```

Increasing the limit is not a general solution: very deep recursion can still exhaust available stack resources. For deep linear processes, an iterative implementation is often safer.

Python does not generally perform tail-call elimination. A tail-recursive function should not be assumed to use constant stack space.

## 11. Where Recursion Appears in Computer Science

- Tree traversal: visiting nodes in a tree.
- Graph algorithms: depth-first search.
- Sorting: Merge Sort and Quick Sort.
- Search: recursive Binary Search.
- Parsing: processing nested expressions and syntax trees.
- Backtracking: exploring combinations, paths, or configurations.
- Divide and Conquer: breaking a problem into smaller instances.

## 12. Recursion in AI/LLM Engineering

Recursion is not the main mechanism behind every LLM pipeline, but it is useful in supporting systems:

- Traversing nested JSON, document trees, or abstract syntax trees.
- Walking hierarchical configuration structures.
- Exploring nested tool or workflow structures.
- Implementing tree-based algorithms and search.

For production systems, consider maximum input depth, stack limits, malformed or cyclic structures, and whether an explicit stack or iterative traversal would be safer.

## 13. Key Takeaways

1. Recursion is a function calling itself on a smaller problem.
2. Every sound recursive solution needs a base case and a progress-making recursive case.
3. Each active call uses a stack frame.
4. Calls build up toward the base case and then unwind.
5. Recursion can make tree-shaped and divide-and-conquer problems easier to express.
6. Recursion can use significant stack space and may repeat work.
7. Iteration is often preferable for simple repetition or very deep linear processes.
8. Always analyse both time complexity and call-stack space.
