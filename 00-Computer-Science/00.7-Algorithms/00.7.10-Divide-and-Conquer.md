# Module 00.7.10 — Divide and Conquer

## 1. What Is Divide and Conquer?

**Divide and Conquer** is an algorithm design strategy that solves a problem by breaking it into smaller subproblems of the same or a related kind.

The standard strategy has three stages:

1. **Divide:** Break the original problem into smaller subproblems.
2. **Conquer:** Solve the subproblems, often recursively.
3. **Combine:** Use the subproblem results to construct the solution to the original problem.

Some algorithms have little or no explicit combine work. The general strategy still applies.

## 2. The Core Idea

Suppose a problem of size `n` can be divided into smaller problems.

Instead of solving the entire problem in one step:
- Break it into smaller pieces.
- Solve each smaller piece.
- Combine the answers when necessary.

The approach is especially useful when smaller instances are easier to solve and the original problem can be reconstructed from their results.

## 3. Example: Merge Sort

Merge Sort is a classic Divide and Conquer algorithm.

### Divide

Split the list into two halves:

```text
[38, 12, 27, 43, 9, 31, 18, 25]

[38, 12, 27, 43]       [9, 31, 18, 25]
```

Continue splitting until each sublist has one element.

### Conquer

A one-element list is already sorted. Recursively sorting the smaller halves produces sorted sublists.

### Combine

Merge the sorted sublists:

```text
[12, 38]       [27, 43]
[12, 27, 38, 43]
```

Continue until one fully sorted list remains.

Merge Sort performs its main ordering work during the combine phase.

## 4. Example: Quick Sort

Quick Sort also uses a Divide and Conquer strategy, but its partitioning differs from Merge Sort.

### Divide

Choose a pivot and partition the array:
- Values on one side belong before the pivot.
- Values on the other side belong after the pivot.

The pivot reaches its final sorted position during partitioning.

### Conquer

Recursively sort the left and right partitions.

### Combine

There is no separate merge operation. Once both sides are sorted, their positions around the pivot already form the sorted array.

## 5. Example: Binary Search

Binary Search applies a related divide-and-reduce idea to a **sorted** collection.

1. Inspect the middle element.
2. If it matches the target, return its position.
3. If the target is smaller, continue in the left half.
4. If the target is larger, continue in the right half.
5. Repeat until found or no elements remain.

Each step discards approximately half of the remaining search space.

For an array of `n` elements, the number of steps is O(log n).

Binary Search is often described as a decrease-and-conquer algorithm because it continues with only one smaller subproblem, rather than solving two or more subproblems and combining their results. It shares the important idea of reducing the problem size substantially at each step.

## 6. Recurrence Relations

A **recurrence relation** describes the running time of a recursive algorithm in terms of the running time on smaller inputs.

A common Divide and Conquer recurrence is:

\[
T(n) = aT(n/b) + f(n)
\]

Where:
- `T(n)` is the running time for input size `n`.
- `a` is the number of recursive subproblems.
- `n/b` is the approximate size of each subproblem.
- `f(n)` is the work done outside the recursive calls, such as dividing or combining.

This is a general model; not every recursive algorithm has exactly this form.

### Merge Sort recurrence

Merge Sort creates two subproblems of approximately half the original size. Merging takes linear time:

\[
T(n) = 2T(n/2) + O(n)
\]

There are two recursive calls, each on approximately `n/2` elements, plus O(n) merge work.

The resulting time complexity is:

\[
O(n \log n)
\]

### Binary Search recurrence

Binary Search makes one recursive call on approximately half the input and performs constant additional work:

\[
T(n) = T(n/2) + O(1)
\]

The resulting time complexity is:

\[
O(\log n)
\]

## 7. The Master Theorem: A Useful Recurrence Shortcut

For recurrences of the form:

\[
T(n) = aT(n/b) + \Theta(n^d)
\]

compare the recursive-work scale \(n^{\log_b a}\) with the non-recursive work \(n^d\).

A simplified statement of the three common cases:

1. If \(d < \log_b a\), then \(T(n) = \Theta(n^{\log_b a})\).
2. If \(d = \log_b a\), then \(T(n) = \Theta(n^d \log n)\).
3. If \(d > \log_b a\), then, under the theorem's regularity condition, \(T(n) = \Theta(n^d)\).

Examples:

- Merge Sort: \(T(n)=2T(n/2)+\Theta(n)\). Here \(a=2\), \(b=2\), and \(d=1\). Since \(\log_2 2=1\), the result is \(\Theta(n\log n)\).
- Binary Search: \(T(n)=T(n/2)+\Theta(1)\). Here \(a=1\), \(b=2\), and \(d=0\). Since \(\log_2 1=0\), the result is \(\Theta(\log n)\).

The Master Theorem applies only when the recurrence fits its required form and conditions. Other recurrences may need a recursion tree, substitution, or another method.

## 8. Divide and Conquer vs Dynamic Programming

Both techniques solve problems by working with smaller subproblems, but they differ in how those subproblems relate.

| Aspect | Divide and Conquer | Dynamic Programming |
|---|---|---|
| Subproblems | Often independent | Often overlap |
| Repeated work | Usually limited when subproblems are independent | Avoided by storing solved results |
| Main techniques | Recursion and combining results | Memoization or tabulation |
| Examples | Merge Sort, Quick Sort | Fibonacci with memoization, knapsack |

### Divide and Conquer

Merge Sort divides the input into separate left and right sections. Those sections can be sorted independently.

### Dynamic Programming

Naive recursive Fibonacci recalculates the same values many times. Dynamic Programming stores previously computed results so each needed subproblem can be solved once.

The distinction is not simply recursion versus no recursion: Dynamic Programming can be implemented recursively with memoization or iteratively with tabulation.

## 9. Advantages

- Breaks complex problems into manageable smaller problems.
- Often leads to clear recursive implementations.
- Can produce efficient algorithms, such as O(n log n) sorting.
- Independent subproblems may be solved in parallel.
- Encourages modular reasoning and correctness proofs.

## 10. Limitations and Trade-offs

- Recursive calls consume stack space.
- Combining results may require additional memory.
- Uneven divisions can lead to poor performance, as in Quick Sort's worst case.
- Subproblems that overlap heavily may repeat work unless memoization or Dynamic Programming is used.
- Parallel execution can add scheduling and communication overhead.

## 11. Connection to AI/LLM Engineering

Divide and Conquer is useful as a general systems design idea:

- Split large documents into chunks before processing.
- Process independent chunks separately, then aggregate or summarize the results.
- Partition large datasets into manageable batches.
- Build hierarchical retrieval or analysis workflows.
- Parallelize independent data-processing tasks where overhead is justified.

For example, a long-document summarization workflow might:
1. Divide a document into chunks.
2. Summarize each chunk.
3. Combine the chunk summaries into a document-level summary.

This is a practical divide-process-combine pattern. Chunking introduces its own design concerns, such as preserving context across chunk boundaries and avoiding duplicated or missing information.

## 12. How to Recognize Divide and Conquer

When examining an algorithm, ask:

1. Does it break a problem into smaller subproblems?
2. Are those subproblems solved independently or recursively?
3. How many subproblems are created?
4. How large is each subproblem?
5. What work happens outside the recursive calls?
6. Must the results be combined?
7. What recurrence describes the total work?

These questions help derive the time and space complexity rather than memorizing it.

## 13. Key Takeaways

1. Divide and Conquer has three stages: divide, conquer, and combine.
2. Merge Sort divides the input, recursively sorts both halves, and merges them.
3. Quick Sort partitions around a pivot and recursively sorts the partitions; it does not need a separate merge step.
4. Binary Search repeatedly halves the search space and is commonly classified as decrease and conquer.
5. Recurrence relations model the running time of recursive algorithms.
6. Merge Sort uses \(T(n)=2T(n/2)+O(n)\), giving O(n log n) time.
7. Binary Search uses \(T(n)=T(n/2)+O(1)\), giving O(log n) time.
8. Dynamic Programming is especially useful when subproblems overlap and results can be reused.
