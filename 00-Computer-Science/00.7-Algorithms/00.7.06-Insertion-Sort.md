# Module 00.7.06 — Insertion Sort

## 1. What is Insertion Sort?

Insertion Sort builds a sorted portion of the array one element at a time. It takes the next element from the unsorted portion and inserts it into the correct position in the already-sorted portion.

A useful analogy is arranging playing cards in your hand: take a new card and insert it where it belongs among the cards already arranged.

## 2. Sorted and unsorted portions

Example: `[5, 3, 8, 2, 1]`.

Initially, the first element is treated as a sorted portion:

```text
[5] | [3, 8, 2, 1]
sorted   unsorted
```

- Insert 3 before 5: `[3, 5, 8, 2, 1]`.
- Insert 8: it is already greater than 5, so the prefix remains `[3, 5, 8]`.
- Insert 2 by shifting 8, 5 and 3 right: `[2, 3, 5, 8, 1]`.
- Insert 1: `[1, 2, 3, 5, 8]`.

## 3. Python implementation

```python
def insertion_sort(numbers):
    for i in range(1, len(numbers)):
        key = numbers[i]
        j = i - 1

        while j >= 0 and numbers[j] > key:
            numbers[j + 1] = numbers[j]
            j -= 1

        numbers[j + 1] = key

    return numbers
```

## 4. Important variables and operations

**`i` — next element to insert**

```python
for i in range(1, len(numbers)):
```

The first element is treated as a sorted portion of length one. The outer loop processes each remaining element.

**`key` — value being inserted**

```python
key = numbers[i]
```

Save the current value before shifting other elements, so it is not overwritten.

**`j` — scan backwards**

```python
j = i - 1
```

Start immediately before the key and move left through the sorted portion.

**Shift larger elements right**

```python
while j >= 0 and numbers[j] > key:
    numbers[j + 1] = numbers[j]
    j -= 1
```

Elements greater than the key are shifted right to make room.

**Insert the key**

```python
numbers[j + 1] = key
```

When the loop stops, `j + 1` is the correct insertion position.

## 5. Why `j >= 0` matters

This condition prevents the scan from moving before index 0.

Python evaluates `and` from left to right and short-circuits. If `j >= 0` is false, it does not evaluate `numbers[j] > key`.

If the key is smaller than every element in the sorted portion, `j` becomes `-1`, so `j + 1` is index 0.

## 6. Shifting rather than repeatedly swapping

For `[5, 8, 3, 10]`, when processing index 2:
- Save `key = 3`.
- Shift 8 right.
- Shift 5 right.
- Insert the saved key at index 0.

Result: `[3, 5, 8, 10]`.

Insertion Sort shifts larger elements and inserts the key once; it does not repeatedly swap the key with every neighbour.

## 7. Correctness: loop invariant

A **loop invariant** is a property that remains true at a defined point during each iteration.

For Insertion Sort:

**Before each outer-loop iteration at index `i`, the portion `numbers[0:i]` is sorted.**

Each iteration inserts `numbers[i]` into its correct position within that sorted portion. The sorted prefix therefore grows by one element. When the outer loop finishes, the entire list is sorted.

## 8. Time and space complexity

| Case | Time | Explanation |
|---|---:|---|
| Best — already sorted | O(n) | One comparison per new element, no shifts |
| Average | O(n²) | Elements typically need some shifting |
| Worst — reverse sorted | O(n²) | Each new element shifts across the sorted portion |

Worst-case shifts grow like:

`1 + 2 + 3 + ... + (n - 1) = n(n - 1) / 2 = O(n²)`

Properties:
- Auxiliary space: O(1).
- In-place: Yes.
- Stable: Yes, when shifting only elements strictly greater than the key (`>`).
- Adaptive: Yes; it does less work on already or nearly sorted input.

## 9. Where Insertion Sort is useful

Despite O(n²) average and worst-case time, it is useful for:
- Small datasets.
- Nearly sorted data.
- Incrementally arriving elements.
- Small subarrays inside hybrid sorting algorithms.

Timsort uses techniques related to binary insertion sort when extending small runs.

## 10. Bubble Sort vs Insertion Sort

| Characteristic | Bubble Sort | Insertion Sort |
|---|---|---|
| Main operation | Adjacent comparisons and swaps | Shifting and insertion |
| Best time (optimized Bubble Sort) | O(n) | O(n) |
| Average time | O(n²) | O(n²) |
| Worst time | O(n²) | O(n²) |
| Auxiliary space | O(1) | O(1) |
| Stable | Yes, with strict `>` swap condition | Yes, with strict `>` shift condition |
| Adaptive | With early-exit optimization | Yes |

Insertion Sort is often more practical than Bubble Sort for small or nearly sorted data because it shifts elements into place rather than repeatedly swapping adjacent pairs.

## Key takeaways

1. Insertion Sort grows a sorted prefix one element at a time.
2. `key` stores the value currently being inserted.
3. Larger values are shifted right to make room.
4. `j + 1` is the insertion position after the backward scan stops.
5. The sorted prefix is maintained throughout the algorithm.
6. Best-case time is O(n); average and worst-case time are O(n²).
7. Auxiliary space is O(1); the algorithm is stable and adaptive as implemented.
