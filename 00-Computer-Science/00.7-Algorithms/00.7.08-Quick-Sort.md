# Module 00.7.08 — Quick Sort

## 1. What Is Quick Sort?

Quick Sort is a comparison-based sorting algorithm that uses a partitioning strategy closely related to **Divide and Conquer**.

Its main steps are:

1. Choose a **pivot** element.
2. **Partition** the array so that values smaller than the pivot are placed on one side and larger values on the other.
3. Recursively apply the same process to the left and right partitions.
4. Stop when a partition contains zero or one element.

Unlike Merge Sort, Quick Sort does most of its work during partitioning. It does not need a separate merge step afterward.

## 2. Pivot and Partition

A pivot is the value used to divide the current portion of the array.

After partitioning, the pivot is placed in its final sorted position:
- Values on its left are less than or equal to it, depending on the partition scheme.
- Values on its right are greater than it, depending on the partition scheme.

The two sides are not necessarily sorted yet. They are sorted by the recursive calls.

Example input:

```python
[8, 3, 1, 7, 0, 10, 2]
```

If `7` is chosen as the pivot, one valid partition result is:

```text
[3, 1, 0, 2]  7  [8, 10]
```

The exact order inside each side may differ. The important property is that the left side contains values no greater than the pivot and the right side contains values greater than the pivot.

## 3. Lomuto Partition Scheme

One commonly taught partition method is the Lomuto scheme. It often chooses the final element as the pivot.

```python
def partition(arr, low, high):
    pivot = arr[high]
    boundary = low - 1

    for current in range(low, high):
        if arr[current] <= pivot:
            boundary += 1
            arr[boundary], arr[current] = arr[current], arr[boundary]

    arr[boundary + 1], arr[high] = arr[high], arr[boundary + 1]
    return boundary + 1
```

### What the variables mean

- `low`: first index of the current section.
- `high`: last index of the current section.
- `pivot`: chosen pivot value.
- `boundary`: end of the region containing values less than or equal to the pivot.
- `current`: scans the section from left to right.

When a value is less than or equal to the pivot, it is swapped into the region on the left. At the end, the pivot is swapped into the position immediately after that region.

The function returns the pivot's final index.

## 4. Complete Quick Sort Implementation

```python
def partition(arr, low, high):
    pivot = arr[high]
    boundary = low - 1

    for current in range(low, high):
        if arr[current] <= pivot:
            boundary += 1
            arr[boundary], arr[current] = arr[current], arr[boundary]

    arr[boundary + 1], arr[high] = arr[high], arr[boundary + 1]
    return boundary + 1


def quick_sort(arr, low, high):
    if low < high:
        pivot_index = partition(arr, low, high)

        quick_sort(arr, low, pivot_index - 1)
        quick_sort(arr, pivot_index + 1, high)


numbers = [8, 3, 1, 7, 0, 10, 2]
quick_sort(numbers, 0, len(numbers) - 1)
print(numbers)
# [0, 1, 2, 3, 7, 8, 10]
```

This implementation sorts the list **in place**. It modifies the original list and does not return a new sorted list.

The recursive calls exclude the pivot index because the pivot is already in its final sorted position.

## 5. Base Case

The condition is:

```python
if low < high:
```

If `low` is equal to `high`, the section contains one element. If `low` is greater than `high`, the section is empty. Both are already sorted, so recursion stops.

## 6. Time Complexity

Quick Sort's performance depends on how balanced the partitions are.

| Case | Partition shape | Time complexity |
|---|---|---:|
| Best | Approximately equal halves | O(n log n) |
| Average | Partitions are reasonably balanced on average | O(n log n) |
| Worst | One side has nearly all elements | O(n²) |

### Why is the best/average case O(n log n)?

When partitions are reasonably balanced:
- There are approximately O(log n) levels of recursive partitioning.
- Each level performs O(n) total partition work.

Therefore:

\[
O(n) \times O(\log n) = O(n \log n)
\]

### Why can the worst case be O(n²)?

If the pivot repeatedly becomes the smallest or largest value, the partitions become extremely unbalanced:

```text
n
n - 1
n - 2
n - 3
...
1
```

The total work is approximately:

\[
(n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}
\]

Therefore, worst-case time is O(n²).

Choosing the last element as pivot can produce this behaviour on already sorted or reverse-sorted input.

## 7. Space Complexity

Quick Sort partitions the array in place, so the partition operation itself uses O(1) extra space.

However, recursive calls use the call stack:
- Average/balanced recursion depth: O(log n).
- Worst-case recursion depth: O(n).

Therefore, auxiliary space is O(log n) on average and O(n) in the worst case for this recursive implementation.

## 8. Properties and Trade-offs

| Property | Quick Sort |
|---|---|
| Type | Comparison-based |
| Strategy | Partitioning / Divide and Conquer |
| Best time | O(n log n) |
| Average time | O(n log n) |
| Worst time | O(n²) |
| Average auxiliary space | O(log n) |
| Worst auxiliary space | O(n) |
| In-place | Yes, for this partitioning implementation |
| Stable | No, generally not |
| Adaptive | Generally no |

### Why is Quick Sort generally unstable?

Swapping elements during partitioning can change the relative order of equal-key elements. Standard in-place Quick Sort does not guarantee that equal elements retain their original order.

### Why can Quick Sort be fast in practice?

- It works in place for common implementations.
- It has good cache locality when operating on arrays.
- Its average-case performance is O(n log n).
- Its inner partitioning loop is relatively simple.

## 9. Improving Pivot Selection

A poor pivot can cause highly unbalanced partitions. Common strategies include:

- **Random pivot:** Choose a pivot randomly to reduce the likelihood of repeatedly encountering bad partitions.
- **Median-of-three:** Choose the median of the first, middle, and last values as the pivot.
- **Three-way partitioning:** Divide values into less-than, equal-to, and greater-than regions. This can help when many duplicate values occur.

These strategies reduce the chance of poor performance but do not change the basic worst-case O(n²) bound for ordinary Quick Sort.

## 10. Quick Sort vs Merge Sort

| Feature | Quick Sort | Merge Sort |
|---|---|---|
| Main operation | Partition | Merge |
| Best time | O(n log n) | O(n log n) |
| Average time | O(n log n) | O(n log n) |
| Worst time | O(n²) | O(n log n) |
| Auxiliary space | O(log n) average stack | O(n) for typical array implementation |
| In-place | Common implementations are | Typical array implementation is not |
| Stable | Generally no | Yes, with correct tie handling |

**Key distinction:** Quick Sort rearranges elements around a pivot; Merge Sort combines independently sorted halves.

## 11. Python in Practice

For ordinary Python application code, prefer the built-in sorting tools:

```python
numbers = [8, 3, 1, 7, 0, 10, 2]

sorted_numbers = sorted(numbers)  # returns a new list
numbers.sort()                    # modifies the original list
```

Python's built-in list sort uses Timsort, not this educational Quick Sort implementation. Timsort is stable and has O(n log n) worst-case time.

## 12. Key Takeaways

1. Quick Sort chooses a pivot and partitions the current array around it.
2. The pivot reaches its final sorted position during partitioning.
3. Recursive calls sort the sections on either side of the pivot.
4. Average time is O(n log n), but worst-case time is O(n²).
5. The common in-place implementation uses little auxiliary memory apart from its recursion stack.
6. Standard Quick Sort is generally unstable.
7. Pivot selection strongly influences performance.
8. Python application code should normally use `sorted()` or `.sort()` rather than a hand-written Quick Sort.
