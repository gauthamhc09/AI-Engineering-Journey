# Module 00.7.02 --- Linear Search

## 1. What is Linear Search?

**Linear Search** (also called sequential search) checks elements one at
a time until: - the target is found; or - all elements have been
checked.

It does not require the input to be sorted.

## 2. Intuition

Imagine looking for a particular book on a shelf where the books are not
arranged in any order. You inspect each book from left to right until
you find the one you want.

That is Linear Search.

## 3. Basic Python implementation

``` python
def linear_search(numbers, target):
    for index in range(len(numbers)):
        if numbers[index] == target:
            return index

    return -1
```

Example:

``` python
numbers = [12, 5, 8, 20, 3]
print(linear_search(numbers, 20))  # 3
print(linear_search(numbers, 99))  # -1
```

The function returns the **index** of the first matching element. It
returns `-1` when the target is absent.

## 4. Step-by-step execution

Given:

``` python
numbers = [12, 5, 8, 20, 3]
target = 20
```

  Check     Index   Value Comparison
  ------- ------- ------- ---------------
  1             0      12 12 == 20? No
  2             1       5 5 == 20? No
  3             2       8 8 == 20? No
  4             3      20 20 == 20? Yes

The function returns `3` immediately. It does not inspect the remaining
elements.

## 5. Why does it return an index?

An index identifies the position of an element in a sequence.

``` python
numbers = [5, 8, 12, 20]

# Index:  0  1   2   3
# Value:  5  8  12  20
```

The value `20` is at index `3`. The index and the value are not
interchangeable.

## 6. Early termination

The `return index` statement exits the function as soon as a match is
found.

This is useful because: - unnecessary comparisons are avoided; - the
first matching position is returned; - the algorithm does not continue
scanning after success.

## 7. Handling duplicates

Consider:

``` python
numbers = [5, 8, 12, 8, 20, 8, 30]
target = 8
```

The function returns index `1`, the first occurrence. It stops there, so
it does not inspect the later occurrences.

If every matching index is required, the algorithm must continue
scanning:

``` python
def find_all(numbers, target):
    matches = []

    for index in range(len(numbers)):
        if numbers[index] == target:
            matches.append(index)

    return matches
```

For the example above, the result is `[1, 3, 5]`.

## 8. Loop invariant and correctness intuition

A **loop invariant** is a statement that remains true at the start of
every loop iteration.

For Linear Search, before checking index `i`, the invariant is:

> The target does not occur at any index before `i`.

Initially, `i = 0`, so there are no earlier indexes to check; the
statement is true.

-   If the current value is not the target, moving to the next index
    preserves the invariant.
-   If the current value equals the target, all earlier positions have
    already been checked and ruled out. Therefore, the current index is
    the first occurrence.
-   If the loop finishes, every index has been checked and the target is
    absent.

This explains why the algorithm is correct.

## 9. Time complexity

Let `n` be the number of elements.

  ------------------------------------------------------------------------
  Case                       Comparisons Time complexity  Explanation
  ---------------- --------------------- ---------------- ----------------
  Best                                 1 O(1)             Target is the
                                                          first element

  Average              Proportional to n O(n)             Typically, a
                                                          substantial part
                                                          of the list is
                                                          inspected

  Worst                                n O(n)             Target is last
                                                          or absent
  ------------------------------------------------------------------------

The worst-case number of comparisons grows linearly with the input size.

For example: - 10 elements: up to 10 comparisons; - 1,000 elements: up
to 1,000 comparisons; - 1,000,000 elements: up to 1,000,000 comparisons.

## 10. Space complexity

The implementation uses a fixed number of extra variables (`index`,
`target`, and references to the input).

Its **auxiliary space complexity is O(1)**.

The input list itself is not counted as extra space.

The `find_all` version uses a result list. If there are `k` matches,
that result requires O(k) additional space.

## 11. Edge cases

  Input situation            Expected behavior
  -------------------------- ------------------------------------------
  Empty list                 Return `-1`
  Target at first position   Return `0`
  Target at last position    Return last index
  Target absent              Return `-1`
  Duplicate targets          Return first occurrence
  Single-element list        Return `0` if it matches; otherwise `-1`

## 12. When is Linear Search useful?

Use it when: - the collection is unsorted; - the collection is small; -
only one search is needed and sorting would cost more; - the data
structure does not support efficient random access; - a simple scan is
sufficient.

Linear Search is not necessarily the best choice for repeated searches
over a large collection. In that situation, sorting or building an index
may be worthwhile.

## 13. Connection to AI/LLM engineering

Linear scans can appear in: - checking a small collection of document
metadata; - inspecting a short list of candidate records; - searching a
small in-memory batch; - applying a simple condition to each item.

For large retrieval systems, scanning every record for every query can
become expensive. Systems often use indexes, hash-based lookup, database
indexes, or specialized vector-search indexes to avoid examining every
item.

## Key takeaways

1.  Linear Search checks elements sequentially.
2.  It works on sorted and unsorted collections.
3.  It can return immediately when it finds a match.
4.  The basic implementation returns the first matching index.
5.  Best-case time is O(1); average and worst-case time are O(n).
6.  Auxiliary space is O(1) for the basic implementation.
