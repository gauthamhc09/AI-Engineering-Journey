# Module 00.7.03 --- Binary Search

## 1. What is Binary Search?

**Binary Search** is a searching algorithm that repeatedly examines the
middle element of a sorted collection and eliminates half of the
remaining search range.

It is much more efficient than Linear Search for large, sorted
collections when the data supports efficient indexed access.

**Prerequisite:** The collection must be sorted in the same order used
by the comparisons.

## 2. Intuition

Imagine searching for a word in a dictionary: 1. Open near the middle.
2. Compare the word you see with the word you want. 3. If the target
comes later alphabetically, ignore the earlier half. 4. If the target
comes earlier, ignore the later half. 5. Repeat in the remaining range.

Each comparison discards roughly half of the remaining candidates.

## 3. Why sorted input is essential

Binary Search uses ordering to decide which half can be discarded.

For ascending data: - if `target > numbers[mid]`, search the right
half; - if `target < numbers[mid]`, search the left half; - if they are
equal, the target has been found.

With unsorted data, these decisions are not reliable. A smaller value
could appear anywhere, so we cannot safely eliminate a half.

## 4. Indexes versus values

This distinction is essential:

-   `low`, `high`, and `mid` are **indexes**.
-   `numbers[mid]` is the **value** stored at the middle index.

Example:

``` python
numbers = [10, 20, 30, 40, 50]

mid = 2
print(mid)          # 2: index
print(numbers[mid]) # 30: value
```

Do not confuse the middle position with the middle value.

## 5. Iterative Binary Search implementation

``` python
def binary_search(numbers, target):
    low = 0
    high = len(numbers) - 1

    while low <= high:
        mid = (low + high) // 2

        if numbers[mid] == target:
            return mid
        elif target > numbers[mid]:
            low = mid + 1
        else:
            high = mid - 1

    return -1
```

Example:

``` python
numbers = [10, 20, 30, 40, 50, 60, 70]

print(binary_search(numbers, 60))  # 5
print(binary_search(numbers, 35))  # -1
```

## 6. Understanding the boundaries

-   `low` is the first index still in the search range.
-   `high` is the last index still in the search range.
-   `mid` is the middle index of the current range.

For an inclusive search range:

``` python
mid = (low + high) // 2
```

When the middle value is too small:

``` python
low = mid + 1
```

When the middle value is too large:

``` python
high = mid - 1
```

The `+ 1` and `- 1` matter: the middle element has already been checked,
so it should be excluded from the next search range.

## 7. Worked example: finding an existing target

Given:

``` python
numbers = [4, 9, 14, 19, 24, 29, 34, 39, 44, 49, 54]
target = 34
```

Initial values:

``` python
low = 0
high = 10
```

  Iteration     low   high   mid   numbers\[mid\] Decision
  ----------- ----- ------ ----- ---------------- -------------------------------
  1               0     10     5               29 Target is larger; `low = 6`
  2               6     10     8               44 Target is smaller; `high = 7`
  3               6      7     6               34 Found

The target is found at index `6` after three comparisons.

Notice that the values (`29`, `44`, `34`) are different from their
indexes (`5`, `8`, `6`).

## 8. Worked example: target does not exist

Given:

``` python
numbers = [10, 20, 30, 40, 50]
target = 35
```

Initial range: `low = 0`, `high = 4`.

  Iteration     low   high   mid   numbers\[mid\] Decision
  ----------- ----- ------ ----- ---------------- --------------------------
  1               0      4     2               30 `35 > 30`, so `low = 3`
  2               3      4     3               40 `35 < 40`, so `high = 2`

Now:

``` python
low = 3
high = 2
```

The search range is empty because `low > high`. The loop condition
`low <= high` is false, so the function returns `-1`.

This means every possible location has been eliminated; the target is
not present.

## 9. Loop invariant and correctness

A useful invariant for this implementation is:

> If the target exists in the collection, its index must be within the
> current inclusive range from `low` to `high`.

Initially, the range covers the entire list, so the invariant is true.

At each iteration: - If the middle value equals the target, the
algorithm returns its index. - If the target is larger, sorted order
proves that the middle element and everything before it cannot be the
target. Moving `low` to `mid + 1` preserves the invariant. - If the
target is smaller, the middle element and everything after it cannot be
the target. Moving `high` to `mid - 1` preserves the invariant.

If the range becomes empty, no possible index remains. Therefore, the
target is absent.

## 10. Time complexity

Each iteration reduces the remaining search range to at most about half
its previous size.

  -----------------------------------------------------------------------
  Case                    Time complexity         Explanation
  ----------------------- ----------------------- -----------------------
  Best                    O(1)                    Target is at the first
                                                  middle position

  Average                 O(log n)                Search range repeatedly
                                                  halves

  Worst                   O(log n)                The algorithm keeps
                                                  halving until found or
                                                  the range is empty
  -----------------------------------------------------------------------

For intuition, a collection of roughly one million elements requires
only about 20 halvings to reduce the range to one candidate, because
`2^20` is approximately one million.

The logarithm is base 2 in this halving process: O(log₂ n). In Big O
notation, the base is conventionally omitted because logarithms with
different constant bases differ only by a constant factor.

## 11. Space complexity

The iterative implementation uses a fixed number of extra variables
(`low`, `high`, and `mid`).

-   **Auxiliary space:** O(1).
-   The input list is not counted as extra space.

A recursive implementation uses call-stack space. Its recursion depth is
O(log n), so its auxiliary stack space is O(log n).

## 12. Duplicates: an important limitation

Consider:

``` python
numbers = [10, 20, 20, 20, 30, 40]
target = 20
```

The standard Binary Search implementation returns a matching occurrence,
but it does not guarantee that it returns the first or last occurrence.

To find the first or last occurrence, modify the algorithm so it
continues searching in the relevant direction after finding a match.

## 13. Edge cases

  -----------------------------------------------------------------------
  Situation                           Expected behavior
  ----------------------------------- -----------------------------------
  Empty list                          `high = -1`; loop does not run;
                                      return `-1`

  One-element list, matching target   Return index `0`

  One-element list, absent target     Return `-1`

  Target is first or last element     Found through normal boundary
                                      updates

  Target is absent                    Eventually `low > high`; return
                                      `-1`

  Duplicate values                    Returns a matching occurrence, not
                                      necessarily first

  Unsorted input                      Standard Binary Search is not valid
  -----------------------------------------------------------------------

## 14. Iterative versus recursive Binary Search

  -----------------------------------------------------------------------
  Property                Iterative               Recursive
  ----------------------- ----------------------- -----------------------
  Repetition mechanism    `while` loop            Function calls

  Auxiliary space         O(1)                    O(log n) call stack

  Main advantage          Memory-efficient and    Can express the
                          straightforward         divide-and-conquer
                                                  structure naturally

  Main trade-off          Requires explicit       Uses additional
                          boundary updates        call-stack memory
  -----------------------------------------------------------------------

In Python, the iterative version is generally a practical default for
ordinary Binary Search.

## 15. Where Binary Search is useful

It is useful when: - data is sorted; - the collection supports efficient
indexed access; - many searches are performed against the same sorted
data; - finding insertion positions or range boundaries is important.

Sorting an unsorted collection first has a cost. If only one search is
needed, sorting may cost more than simply using Linear Search. For
repeated searches, preprocessing and sorting may be worthwhile.

## 16. Connection to AI/LLM engineering

Binary Search can help with ordered data in production systems, for
example: - locating a timestamp in sorted event records; - finding a
boundary in sorted document metadata; - finding insertion positions in
ordered arrays; - identifying a threshold or range boundary in sorted
values.

However, **vector similarity search is not ordinary Binary Search**.
Embedding vectors are searched using similarity measures and specialized
nearest-neighbor indexes or search methods. Binary Search's ordinary
halving logic depends on a sorted one-dimensional ordering.

## Key takeaways

1.  Binary Search repeatedly halves a sorted search range.
2.  Standard Binary Search requires sorted data.
3.  `low`, `high`, and `mid` are indexes; `numbers[mid]` is a value.
4.  If the target is larger than the middle value, set `low = mid + 1`.
5.  If the target is smaller, set `high = mid - 1`.
6.  The loop continues while `low <= high`.
7.  If `low > high`, the target is absent.
8.  Time complexity is O(log n); iterative auxiliary space is O(1).
9.  Standard Binary Search does not guarantee the first occurrence among
    duplicates.
10. Sorting before searching has a preprocessing cost that must be
    considered.
