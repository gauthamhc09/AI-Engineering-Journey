## 1. What is Merge Sort?

Merge Sort is a comparison-based sorting algorithm based on **Divide and Conquer**.

It follows three broad steps:

1. **Divide:** Break the array into smaller parts.
2. **Conquer:** Sort the smaller parts recursively.
3. **Combine:** Merge the sorted parts into one sorted array.

The central idea is to keep dividing until each subarray contains one element. A single-element array is already sorted. Then combine these small arrays in sorted order.

## 2. Example input

```python
numbers = [38, 12, 27, 43, 9, 31, 18, 25]
```

## 3. Divide phase

Repeatedly split the array:

```text
                 [38, 12, 27, 43, 9, 31, 18, 25]
                         /                 \
              [38, 12, 27, 43]       [9, 31, 18, 25]
                 /       \                /       \
             [38, 12]  [27, 43]       [9, 31]  [18, 25]
              /   \     /   \          /   \     /   \
            [38] [12] [27] [43]      [9] [31] [18] [25]
```

The process stops when each subarray contains one element. Each one-element subarray is already sorted.

## 4. Merge phase

Now combine the small sorted arrays.

**First-level merges**

```text
[38] and [12]  -> [12, 38]
[27] and [43]  -> [27, 43]
[9]  and [31]  -> [9, 31]
[18] and [25] -> [18, 25]
```

**Second-level merge**

Merge `[12, 38]` and `[27, 43]` by comparing the front elements:
- Compare 12 and 27: take 12.
- Compare 38 and 27: take 27.
- Compare 38 and 43: take 38.
- Append the remaining 43.

Result: `[12, 27, 38, 43]`.

Similarly, `[9, 31]` and `[18, 25]` merge into `[9, 18, 25, 31]`.

**Final merge**

Merge `[12, 27, 38, 43]` and `[9, 18, 25, 31]`.

Final sorted result:

```python
[9, 12, 18, 25, 27, 31, 38, 43]
```

## 5. Dividing vs merging

- Dividing breaks the original problem into smaller subproblems. It does not itself put values into sorted order.
- Merging combines sorted subarrays by comparing their front elements and building a sorted result.

This distinction is central to Merge Sort.

## 6. Complexity and properties

| Case | Time complexity |
|---|---:|
| Best | O(n log n) |
| Average | O(n log n) |
| Worst | O(n log n) |

Typical array-based Merge Sort properties:

| Property | Merge Sort |
|---|---|
| Comparison-based | Yes |
| Stable | Yes, with correct tie handling |
| Adaptive | Generally no |
| In-place | No, in the typical array implementation |
| Auxiliary space | O(n) |

Merge Sort achieves O(n log n) time consistently, but typical array implementations need O(n) auxiliary memory for merging.

## Key takeaways so far

1. Merge Sort uses Divide and Conquer.
2. It repeatedly divides the array until subarrays contain one element.
3. Single-element arrays are already sorted.
4. The merge phase combines sorted subarrays by comparing their front elements.
5. Its best-, average-, and worst-case time complexities are O(n log n).
6. Typical array-based implementations use O(n) auxiliary space.
7. Merge Sort is stable when equal elements are handled with the appropriate tie rule.
