# Module 00.7.01 --- Algorithmic Thinking

## 1. What is an algorithm?

An **algorithm** is a finite, well-defined sequence of steps for solving
a problem or completing a task.

An algorithm: - accepts zero or more inputs; - performs a sequence of
unambiguous operations; - produces an output or result; - must
eventually terminate.

A Python program is one way to implement an algorithm. The algorithm is
the underlying problem-solving method; the code is its implementation in
a programming language.

## 2. Algorithmic thinking

**Algorithmic thinking** means translating a problem into a precise
sequence of steps that can be executed and checked.

A useful process is:

1.  **Understand the problem** --- identify exactly what is being asked.
2.  **Identify inputs and outputs** --- define what information is
    available and what result is required.
3.  **Identify constraints** --- consider input size, ordering,
    duplicates, empty inputs, memory limits, and performance
    requirements.
4.  **Choose a strategy** --- select a suitable approach or data
    structure.
5.  **Write the steps** --- express the solution clearly, using
    pseudocode if helpful.
6.  **Check correctness** --- reason about why the steps always produce
    the required result.
7.  **Analyze efficiency** --- estimate time and auxiliary space
    complexity.
8.  **Test edge cases** --- check unusual but valid inputs.

Do not start by writing code before understanding the problem and its
constraints.

## 3. Problem-solving example: searching a list

Suppose we need to find the value `25` in:

``` python
numbers = [10, 25, 30, 45, 60]
```

Possible strategy: inspect elements one by one until the target is
found.

But if the input is sorted, another strategy may be possible: repeatedly
inspect the middle and eliminate half of the remaining range.

The choice depends on the properties of the input. An algorithm is not
automatically suitable just because it is faster in some situations.

## 4. Linear Search vs Binary Search

  -----------------------------------------------------------------------
  Property                Linear Search           Binary Search
  ----------------------- ----------------------- -----------------------
  Basic idea              Check elements          Check the middle and
                          sequentially            eliminate half

  Requires sorted input?  No                      Yes, for the standard
                                                  algorithm

  Worst-case time         O(n)                    O(log n)

  Typical use             Unsorted or small       Sorted collections with
                          collections             efficient indexed
                                                  access
  -----------------------------------------------------------------------

### Important: Binary Search requires ordering

Binary Search decides which half can be discarded by comparing the
target with the middle value. This decision is only reliable when the
data is sorted according to the same ordering.

For example, with unsorted data:

``` python
numbers = [40, 10, 70, 20, 50]
```

If the middle value is `70` and the target is `20`, we cannot safely
conclude that the target is on either side. Smaller and larger values
may appear anywhere.

For unsorted data, use Linear Search initially. Alternatively, sort the
data and then use Binary Search, but account for the cost of sorting and
any need to preserve original positions.

## 5. Correctness and efficiency are different

A solution must first be **correct**: it must produce the required
result for all valid inputs.

Then evaluate its efficiency: - **Time complexity** describes how the
amount of work grows with input size. - **Space complexity** describes
how memory usage grows with input size. - **Auxiliary space** refers to
extra memory used by the algorithm, excluding the input itself.

A fast incorrect algorithm is not a good solution.

## 6. Practical checklist

Before implementing an algorithm, ask:

-   What exactly is the input?
-   What output is expected?
-   What assumptions can I rely on?
-   Is the data sorted?
-   Can values be duplicated?
-   What should happen for an empty input?
-   What should happen when the target is absent?
-   Can I explain why the algorithm is correct?
-   What are its time and space costs?

## 7. Connection to AI/LLM engineering

Algorithmic thinking appears throughout production AI systems:

-   choosing how to retrieve records from metadata;
-   deciding whether to sort, filter, or search first;
-   selecting data structures for queues, caches, and indexes;
-   designing batch-processing workflows;
-   reasoning about latency and memory as datasets grow.

For example, a retrieval pipeline may first filter documents by
metadata, then rank the remaining candidates. Understanding the problem
and constraints helps determine which operations should happen first.

## Key takeaways

1.  An algorithm is a precise, finite procedure for solving a problem.
2.  Understand inputs, outputs, constraints, and edge cases before
    coding.
3.  Choose an algorithm based on the properties of the data and the
    problem.
4.  Binary Search cannot be applied directly to arbitrary unsorted data.
5.  Correctness comes before performance optimization.
