# Module 00.8.02 --- Client and Server

## Learning objective

Understand the client-server model, the request-response pattern, why
applications use this architecture, and how it applies to React,
FastAPI, databases and AI services.

## 1. What is a client?

A **client** is a device or software application that requests a service
or resource from another system.

Examples: - A browser requesting a webpage - A React frontend requesting
portfolio information - A Python script calling an external API - A
mobile app requesting profile data - An AI application requesting an LLM
response

A client does not have to be a physical computer. It can be software
running on a computer.

## 2. What is a server?

A **server** is a computer or software application that provides
services or resources to clients.

Examples: - A web server providing webpages - A FastAPI application
providing API responses - A PostgreSQL server providing database
services - An authentication server verifying identities - An LLM
inference service generating responses

A server commonly waits for incoming requests, processes them and sends
responses.

**Important:** A server is not necessarily special hardware. A normal
laptop can run server software. The term primarily describes the role of
providing a service.

## 3. The request-response model

The fundamental client-server interaction is:

``` text
Client  ------ Request ------>  Server

Client  <----- Response ------  Server
```

Typical high-level sequence:

1.  The client initiates a request.
2.  The request travels through a network or local communication
    mechanism.
3.  The server receives the request.
4.  The server processes it.
5.  The server sends a response.
6.  The client processes or displays the response.

HTTP is a widely used protocol for web request-response communication.
It will be covered later.

## 4. Why use client-server architecture?

A central service can provide shared functionality to many clients.

Benefits include: - Centralised business logic - Centralised data
management - Consistent application behaviour - Easier deployment of
backend updates - Centralised authentication and access control - Shared
access to services and resources

It also introduces engineering responsibilities: - **Concurrency:**
handling multiple operations that overlap in time. - **Scalability:**
supporting increasing numbers of users or requests. - **Load
balancing:** distributing incoming requests across servers. - **Fault
tolerance:** continuing to operate when components fail.

## 5. Multiple clients can use one server

A server can handle requests from many clients.

For example, thousands of banking customers can use the same logical
banking service.

The server infrastructure must be designed to handle concurrent requests
and scale as demand grows.

## 6. A server is not the same as a database

Consider a React + FastAPI + PostgreSQL application:

  -----------------------------------------------------------------------
  Component                           Role
  ----------------------------------- -----------------------------------
  React frontend                      Client; requests application data

  FastAPI application                 Application server; handles
                                      requests and business logic

  PostgreSQL                          Database server; stores and
                                      retrieves data
  -----------------------------------------------------------------------

A typical interaction:

``` text
React client
    |
    | Request portfolio data
    v
FastAPI application server
    |
    | Database query
    v
PostgreSQL database server
    |
    | Query result
    v
FastAPI application server
    |
    | API response
    v
React client
```

There are two separate client-server relationships:

1.  React is the client and FastAPI is the server.
2.  FastAPI is the client and PostgreSQL is the server.

**Key principle:** A program can be a server in one relationship and a
client in another. The role depends on the communication taking place,
not on a permanent identity.

## 7. Can client and server run on the same computer?

Yes. They do not need to be separate physical machines.

For example, during local development:

``` text
Your laptop
|
|-- React frontend
|-- FastAPI server
|-- PostgreSQL server
```

These are separate software components running on the same machine.

`localhost` is a hostname that refers to the current computer. For IPv4,
it commonly resolves to `127.0.0.1`; for IPv6, the loopback address is
`::1`.

Example:

``` text
http://localhost:8000
```

A crucial detail: `localhost` refers to the machine making the request.
If a browser on your laptop calls `localhost`, it is trying to reach a
service on your laptop, not a remote backend.

## 8. What happens when you open a website?

At a high level, when you enter a website address in a browser:

1.  The browser acts as the client.
2.  It needs to locate the destination service.
3.  It establishes the required network communication.
4.  It sends a request.
5.  The server processes the request.
6.  A response comes back.
7.  The browser interprets the response and renders the page.

There are additional steps involving DNS, IP addresses, TCP, TLS and
HTTP. These will be studied separately.

## 9. Connection to AI/LLM applications

A RAG application may have this architecture:

``` text
React frontend
      |
      v
FastAPI backend
      |
      +----> LLM provider API
      |
      +----> Embedding API
      |
      +----> Vector database
      |
      +----> PostgreSQL
```

The role of each component depends on the connection: - React requests
services from FastAPI. - FastAPI requests inference from an LLM
provider. - FastAPI queries a vector database. - FastAPI queries
PostgreSQL.

Networking enables these independent components to work together.

## 10. Key takeaways

-   A client requests a service; a server provides it.
-   Clients and servers can be software processes, not just physical
    machines.
-   One server can serve multiple clients.
-   A single program can act as both client and server in different
    relationships.
-   Client and server can run on the same physical computer.
-   Modern backend and AI architectures depend on communication between
    services.
