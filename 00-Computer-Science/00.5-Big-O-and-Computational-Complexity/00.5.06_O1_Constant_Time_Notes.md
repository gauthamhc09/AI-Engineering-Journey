# 00.5.06 --- O(1): Constant Time

## Definition

An operation has **O(1) time complexity** when its work remains bounded
independently of input size, under the assumptions of the analysis. It
does not mean exactly one second or one machine instruction.

## Known list index

``` python
def get_first(numbers):
    return numbers[0]
```

Python list indexing by a known position is typically O(1), whether the
list contains a few elements or millions.

Compare:

``` python
numbers[3]       # O(1): access by known index
80000 in numbers # O(n): worst-case search through a list
```

## Constant work vs. input-dependent work

``` python
def display_first_number(numbers):
    print("Starting")
    print(numbers[0])
    print("Finished")
```

Assuming a non-empty list, this performs a fixed number of operations:
O(1).

A function that loops through every item is O(n) under a
fixed-cost-per-item model.

## Linear search

``` python
def find_value(numbers, target):
    for number in numbers:
        if number == target:
            return number
    return None
```

If the target is first, one comparison may suffice. If it is last or
absent, all `n` elements may be checked. Its worst-case time complexity
is **O(n)**; best-case work is constant. Best, average, and worst cases
are covered later.

## Dictionary lookup

``` python
employee = {"name": "Rahul", "role": "Developer", "salary": 80000}
print(employee["role"])
```

Python dictionary lookup is typically **average-case O(1)**. Hashing
helps locate an entry without scanning all entries in the usual case,
though collisions and other factors mean this is not an unconditional
guarantee.

## Examples and caveats

-   Known Python list index: typically O(1).
-   Simple variable assignment: O(1) under the usual model.
-   Dictionary lookup: average-case O(1).
-   Python list append: **amortized O(1)**, not worst-case O(1) for
    every append; amortized complexity comes later.

## AI Engineering connection

Dictionaries and caches support efficient key-based lookups for document
IDs, user records, and computed results, avoiding repeated list scans.

## Key takeaways

-   O(1) describes constant growth, not a duration.
-   Index access differs from value search.
-   Linear search can be O(n) in the worst case.
-   Check assumptions and whether a claim is average-case or worst-case.
