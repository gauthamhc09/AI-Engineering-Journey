# 00.5.07 --- O(log n): Logarithmic Time

## Core idea

Logarithmic time appears when an algorithm repeatedly reduces the
remaining problem size by a constant factor, such as halving it. Binary
search is the classic example and requires sorted data with efficient
access by position.

## Binary search

1.  Examine the middle element.
2.  If it matches, return.
3.  If the target is smaller, discard the right half.
4.  If the target is larger, discard the left half.
5.  Repeat on the remaining half.

``` python
def binary_search(numbers, target):
    left = 0
    right = len(numbers) - 1

    while left <= right:
        middle = (left + right) // 2
        if numbers[middle] == target:
            return middle
        elif numbers[middle] < target:
            left = middle + 1
        else:
            right = middle - 1
    return -1
```

Example:

``` python
numbers = [10, 20, 30, 40, 50, 60, 70]
print(binary_search(numbers, 50))  # 4
```

## Why logarithmic?

After `k` halvings, the remaining search space is approximately
`n / 2^k`. Reducing it to about one candidate takes roughly `log₂(n)`
halvings. Since `1024 = 2^10`, 10 halvings reduce 1,024 candidates to
about one.

A search may terminate earlier if the target is found. Exact comparison
counts depend on implementation and target.

## Comparison

  -----------------------------------------------------------------------
               Input size     Linear search worst           Binary search
                                             case    approximate halvings
  ----------------------- ----------------------- -----------------------
                       16         Up to 16 checks                 About 4

                    1,024      Up to 1,024 checks                About 10

                1,048,576  Up to 1,048,576 checks                About 20
  -----------------------------------------------------------------------

These are illustrative growth comparisons, not elapsed-time
measurements.

## Assumptions and applications

-   Binary search requires sorted data and efficient positional access.
-   If data must first be sorted, include that sorting cost in the whole
    task.
-   Logarithm base does not change the Big O class because different
    constant bases differ by a constant factor.
-   Tree-based structures and database indexes can use branching to
    locate entries efficiently. Not every AI retrieval system is O(log
    n); vector-search complexity depends on the index and strategy.

## Key takeaways

-   O(log n) grows slowly because each step removes a constant fraction
    of the remaining work.
-   Binary search is a classic O(log n) algorithm.
-   One million candidates can be narrowed down in roughly 20 halvings.
