# Module 00.5.10 — O(n²): Quadratic Time Complexity

## Meaning
An algorithm has quadratic time complexity, `O(n²)`, when its work grows proportionally to the square of the input size under the analyzed model. A common pattern is two nested loops, each running `n` times.

```python
def print_pairs(numbers):
    for first in numbers:
        for second in numbers:
            print(first, second)
```

For `n` elements, this processes `n × n = n²` pairs.

## Scaling

| Input size (`n`) | Pair operations (`n²`) |
|---:|---:|
| 10 | 100 |
| 100 | 10,000 |
| 200 | 40,000 |
| 1,000 | 1,000,000 |

Doubling input size approximately quadruples the work: `(2n)² = 4n²`.

## Duplicate detection
A naive approach compares items pairwise. In the worst case, it performs `n(n - 1) / 2` comparisons, which is `O(n²)`.

```python
def has_duplicates(numbers):
    return len(numbers) != len(set(numbers))
```

For hashable values, the set-based approach is typically average `O(n)` time and uses `O(n)` extra space.

## AI engineering connection
Pairwise comparisons between documents or embeddings can become expensive as the collection grows. Consider whether indexing, filtering, approximate search, or another strategy can reduce comparisons.

## Key takeaways
- Two loops each running `n` times commonly produce `O(n²)` work.
- Doubling `n` produces roughly four times as much work.
- Nested loops are not automatically quadratic; count total iterations.
- A different algorithm may reduce time complexity, sometimes at the cost of extra memory.
