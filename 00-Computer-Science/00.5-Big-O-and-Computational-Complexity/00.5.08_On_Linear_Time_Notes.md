# 00.5.08 --- O(n): Linear Time

## Definition

An algorithm has **O(n) time complexity** when its work grows
proportionally to input size `n`, under the assumptions of the analysis.
If input doubles, work typically doubles.

## Process every element once

``` python
def calculate_sum(numbers):
    total = 0
    for number in numbers:
        total += number
    return total
```

The function visits each element once. Under a fixed-cost-per-element
model, its time complexity is O(n).

``` python
def display_numbers(numbers):
    for number in numbers:
        print(number)
```

This is O(n) under a fixed-cost-per-item model, though actual printing
time depends on I/O and environment.

## Linear search

``` python
def find_value(numbers, target):
    for number in numbers:
        if number == target:
            return number
    return None
```

In the worst case, the target is last or absent, so the function checks
all `n` elements. Worst-case time is O(n). If the target is first, the
function returns after one comparison. Best, average, and worst cases
are covered later.

## Count actual work

Two sequential loops that each run `n` times perform about `n + n = 2n`
iterations. The growth remains O(n), because constant factors do not
change the asymptotic class.

A nested loop is not automatically O(n²). Analyze the total number of
inner iterations. If total work across inner iterations is bounded by
`n`, the overall work may still be O(n). If each iteration itself
performs work that grows with input size, complexity can be greater.

## Linear vs. constant time

``` python
def first_item(items):
    return items[0]
```

Known-index access in a Python list is typically O(1).

``` python
def process_all(items):
    for item in items:
        print(item)
```

Processing every item is O(n) under a fixed-cost-per-item model.

## AI Engineering connection

Linear processing appears when validating every record, calculating sums
or averages, transforming each item, scanning for a value, or processing
each document chunk once. Real costs can vary with document length,
model inference, network calls, and I/O.

## Key takeaways

-   O(n) means work grows proportionally to input size under stated
    assumptions.
-   A single pass through all elements is a common O(n) pattern.
-   Sequential linear passes remain O(n).
-   Analyze actual iteration counts and the cost of work inside each
    iteration.
