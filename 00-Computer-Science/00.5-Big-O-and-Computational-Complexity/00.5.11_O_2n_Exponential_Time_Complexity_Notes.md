# Module 00.5.11 — O(2ⁿ): Exponential Time Complexity

## Meaning
Exponential time can occur when an algorithm explores every combination of binary choices. Each additional binary choice doubles the number of possibilities. With `n` independent binary choices, there are `2ⁿ` combinations.

| Choices (`n`) | Combinations (`2ⁿ`) |
|---:|---:|
| 10 | 1,024 |
| 20 | 1,048,576 |
| 30 | 1,073,741,824 |
| 40 | 1,099,511,627,776 |

## Example: generate binary strings

```python
def generate_binary_strings(n, prefix=""):
    if n == 0:
        print(prefix)
        return
    generate_binary_strings(n - 1, prefix + "0")
    generate_binary_strings(n - 1, prefix + "1")
```

This produces `2ⁿ` strings. Complete runtime also depends on constructing and printing each string; outputting all strings requires work proportional to the total output size.

## Where it appears
- Exploring all subsets or combinations.
- Brute-force configuration search.
- Some recursive algorithms with repeatedly branching call trees.

Recursion is not automatically exponential: analyze the number of calls and the work per call.

## AI engineering connection
Searching every possible action sequence or configuration can become infeasible quickly. Pruning, heuristics, caching/memoization, and approximate search can avoid exploring every possibility.

## Key takeaways
- Each additional binary choice can double the search space.
- Exponential growth becomes impractical quickly.
- The output size itself can impose a large lower bound on runtime.
