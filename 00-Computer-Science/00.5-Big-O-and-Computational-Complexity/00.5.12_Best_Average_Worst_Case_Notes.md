# Module 00.5.12 — Best, Average, and Worst Case

## Why analyze different cases?
An algorithm can do different amounts of work for inputs of the same size. Linear search may find a target immediately, find it near the end, or fail to find it.

```python
def find_value(numbers, target):
    for number in numbers:
        if number == target:
            return True
    return False
```

## Three cases
- **Best case:** Least work for an input size. If the target is first, there is one comparison: `O(1)`.
- **Average case:** Expected work under a specified probability model. If the target is present and equally likely at any position, expected comparisons are `(n + 1) / 2`, giving `O(n)`.
- **Worst case:** Greatest work for an input size. If the target is last or absent, all `n` elements may be checked: `O(n)`.

The average depends on assumptions. If the target may be absent, its probability must also be considered.

## Big O and cases are different
- **Best, average, and worst case** identify which input behavior is analyzed.
- **Big O** describes an asymptotic upper bound on the growth of the analyzed function.

Big O does not inherently mean worst case, although worst-case Big O is commonly reported.

Examples:
- Linear search has `O(1)` best-case time.
- Linear search has `O(n)` worst-case time.
- Under the uniform-position assumption above, average-case time is `O(n)`.

## AI engineering connection
A search over document chunks may find a match immediately, find it near the end, or scan everything. If scanning many chunks is too slow, an index or retrieval structure may be more suitable.
