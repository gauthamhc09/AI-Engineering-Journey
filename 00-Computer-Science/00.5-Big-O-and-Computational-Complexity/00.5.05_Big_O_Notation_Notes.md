# 00.5.05 --- Big O Notation

## Why Big O?

Big O gives us a standard way to describe how an algorithm's resource
requirements grow with input size, independently of a particular
computer or programming language.

**Big O notation describes an asymptotic upper bound on growth.** In
algorithm analysis, it is commonly used to describe time or space
requirements as input size increases.

## Input size and growth

Input size is commonly represented by `n`. For a list, `n` might be the
number of elements.

If a simplified operation-counting model gives `T(n) = 3n + 5`, the
linear term dominates for large `n`, so the growth is described as
**O(n)**. Big O does not preserve every constant and smaller term.

## Examples

**O(1):**

``` python
def get_first(numbers):
    return numbers[0]
```

Accessing a known index in a Python list is typically constant time.

**O(n):**

``` python
def display_numbers(numbers):
    for number in numbers:
        print(number)
```

Each element is processed once under a fixed-cost-per-element model.

**O(n²):**

``` python
def print_pairs(numbers):
    for first in numbers:
        for second in numbers:
            print(first, second)
```

Each of `n` outer iterations runs an inner loop `n` times: `n × n = n²`
pairs. Doubling `n` quadruples the number of pairs. Nested loops do not
automatically mean O(n²); analyze the actual total iteration count.

## Important clarifications

1.  Big O is not elapsed time; O(n) does not mean a particular number of
    seconds.
2.  Big O is not automatically synonymous with worst case. It is an
    asymptotic upper bound, and can be used to describe best-, average-,
    or worst-case behavior depending on the function analyzed.
3.  Big O is not an exact operation count; it describes growth.

## Effect of doubling input

-   O(1): work remains roughly constant.
-   O(n): work roughly doubles.
-   O(n²): work roughly quadruples.
-   O(n log n): work increases by a little more than double for large
    `n`.

These are growth comparisons, not runtime guarantees.

## AI Engineering connection

Big O helps evaluate scalability in document processing, retrieval
pipelines, database access, data transformations, and model-serving
infrastructure. Actual runtime also depends on constants, I/O, hardware,
memory behavior, and implementation.

## Key takeaways

-   Define what `n` represents.
-   Count input-dependent work and identify its growth.
-   State assumptions and distinguish asymptotic growth from elapsed
    time.
