# 00.3.08 — Heap Memory

## Why heap memory matters
```python
def create_users():
    users = ["Gautham", "Ravi", "Priya"]
    return users

my_users = create_users()
print(my_users)
```
The list remains accessible after the function returns because the function's lifetime and the list object's lifetime are not necessarily the same.

## Definition
The **heap** is a region of memory used for dynamically allocated objects and data. In Python, objects such as lists, dictionaries, and class instances are generally allocated in memory managed by the Python runtime, commonly called the Python heap.

An object can outlive the function that created it if references or other retention mechanisms keep it alive.

## Following the example
1. The function starts and Python creates execution state for the call.
2. The runtime allocates memory for the list and its contents as needed.
3. `users` refers to the list object.
4. The function returns a reference to that same object.
5. The caller assigns the reference to `my_users`.
6. The function's local execution state ends, but the list remains accessible through `my_users`.

The list does not need to move from stack to heap when the function returns. In the usual CPython model, it is already managed in heap memory.

## Stack vs. heap

| Call stack | Heap |
|---|---|
| Tracks active calls and execution state | Holds dynamically allocated objects |
| Conventional nested calls follow LIFO | Objects can outlive their creating function |
| Associated with nested function execution | Associated with object allocation and lifetime |

These are conceptual roles; physical layouts vary by language and runtime.

## Is heap always slower?
No. Stack and heap describe different memory-management structures or allocation strategies. Neither label alone determines physical location or access speed. Performance depends on allocation overhead, memory layout, cache locality, and access patterns.

## Backend connection
A FastAPI endpoint may create objects for a response:
```python
def process_request():
    result = {"status": "success", "items": [1, 2, 3]}
    return result
```
These objects can remain alive while the response is processed or serialized. Object retention affects memory usage and can contribute to memory leaks.

## Key takeaways
1. The heap is used for dynamically allocated objects.
2. Python's runtime manages memory for Python objects.
3. An object can outlive its creating function.
4. A returned reference lets the caller access the same object.
5. “Heap” does not automatically mean slower access.
