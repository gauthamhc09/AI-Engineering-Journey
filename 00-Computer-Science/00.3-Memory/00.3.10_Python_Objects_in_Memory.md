# 00.3.10 — Python Objects in Memory

## What is a Python object?
```python
age = 34
name = "Gautham"
scores = [85, 90, 95]
```
Python creates or uses objects representing these values. Three useful conceptual aspects of an object are:
- **Identity:** Which particular object it is.
- **Type:** What kind of object it is.
- **Value:** The data it represents.

This is a conceptual model, not a literal three-field layout required for every object. Actual representation depends on implementation and object type.

## Inspecting an object
```python
scores = [85, 90, 95]
print(type(scores))
print(id(scores))
print(scores)
```
- `type(scores)` reports the type of the object referenced by `scores`.
- `id(scores)` returns an identity value distinguishing the object during its lifetime.
- `scores` displays the list contents.

In CPython, `id()` is typically related to the object's memory address. The Python language specification does not require it to be a raw memory address.

## Names and objects
```python
a = [10, 20]
b = a
```
Both names are associated with references to the same list object. The names are not separate copies, and neither name refers to the other.

```python
b.append(30)
print(a)  # [10, 20, 30]
```
The mutation is visible through both names because they refer to the same mutable object.

## Mutable and immutable objects
**Mutable objects** can change their contents while remaining the same object. Examples: `list`, `dict`, `set`.
```python
items = [1, 2]
items.append(3)
```

**Immutable objects** cannot have their value changed in place. Examples: `int`, `str`; a `tuple` is an immutable container, though it can contain references to mutable objects.
```python
x = 10
x = x + 1
```
Python evaluates the addition and rebinds `x` to the result. It does not mutate the integer object representing `10`.

## What does a list contain?
```python
a = [10, 20]
b = a
```
A Python list stores references to its elements rather than embedding each element's complete object representation directly inside the list. Conceptually, the list holds references to the objects representing `10` and `20`. Normal Python code does not manipulate raw pointers directly.

## Application connection
```python
cache = {"model": "embedding-model", "dimensions": 768}
```
The dictionary is a Python object. Other parts of an application can refer to it, and its lifetime may extend beyond one function call. Understanding objects and references helps explain shared mutable state, caches that retain large objects, and data remaining in memory after a request finishes.

## Common misconceptions
- A Python name is the object itself — **incorrect**; a name is associated with a reference to an object.
- `b = a` creates a copy — **incorrect**; it makes `b` refer to the same object.
- An operation that appears to change an immutable value mutates the same object — **incorrect**; assignment can rebind a name to a result.
- `id()` is always a raw memory address — **incorrect**; it returns an identity value, commonly address-related in CPython.

## Key takeaways
1. Objects have identity, type, and value.
2. `type(x)` reports the type of the referenced object.
3. `id(x)` returns an identity value, not necessarily a portable raw address.
4. Multiple names can refer to one object.
5. Lists store references to their elements.
6. Mutable objects can change in place; immutable objects cannot.
7. Assignment can rebind a name without mutating the previously referenced object.
