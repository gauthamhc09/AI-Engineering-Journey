# 00.3.01 — RAM and Physical Memory

## 1. Why RAM exists

A CPU needs instructions and data to perform work, but the CPU cannot keep an unlimited amount of information in its registers. Computers therefore use a memory hierarchy:

```text
Registers → Cache → RAM → Storage
```

RAM provides relatively large, working memory for the instructions and data used by active programs. It is larger than CPU cache but generally slower.

## 2. What is physical memory?

**Physical memory** is the actual memory hardware installed in a computer. In ordinary computer discussions, this usually means the system's RAM.

For example, a computer with 16 GB of RAM has approximately 16 GB of physical RAM capacity available to the system, subject to hardware and system reservations.

At this stage, focus on the physical layer: the hardware that can hold bits while powered.

## 3. What does RAM contain?

At a basic conceptual level, RAM stores bits—binary states represented as `0` or `1`.

Memory is organized into locations that can be addressed. A simplified illustration is:

```text
Address     Stored bits
1000        01010110
1001        11001001
1002        00001101
1003        10110010
...
```

This is an illustrative model, not a claim about the exact physical layout of a modern RAM chip.

**Key idea:** memory has locations that can be identified by addresses.

## 4. What is a memory address?

An **address** identifies a location in memory. It allows the system to select which location should be accessed.

Conceptually:

```text
Address 1000 → stored bits
Address 1001 → stored bits
Address 1002 → stored bits
```

If the system requests address `1002`, it is asking to access the location identified by that address—not to search for a particular value such as `42`.

A value and the location containing that value are different things.

## 5. What does “random access” mean?

In RAM, “random” does not mean unpredictable. It means a requested address can be accessed without reading every preceding location in sequence.

For example, accessing address `1004` does not conceptually require reading addresses `1000`, `1001`, `1002`, and `1003` first.

## 6. Reading from memory

A simplified conceptual model:

```text
CPU
 │ requests a memory address
 ▼
Memory system
 │ selects the requested location
 ▼
RAM
 │ stored bits are retrieved
 ▼
Data becomes available to the CPU
```

The real hardware path includes memory controllers, caches, and other details. For this lesson, the essential idea is that an address identifies the location to read.

## 7. Writing to memory

A write conceptually provides a target address and data to store:

```text
CPU / memory system
       │ address + data
       ▼
      RAM
       │
       ▼
Bits stored at the selected location
```

For example, a simplified view might represent a location as:

```text
Address 1000 → value 42
```

The actual representation of `42` in memory is a sequence of bits.

## 8. Memory cells and bits

RAM is built from enormous numbers of electronic memory structures. At a simplified level, these structures represent binary states. Groups of bits are organized so that memory can be accessed by address.

```text
Physical RAM
    ↓
Memory structures/cells
    ↓
Bits
    ↓
Groups of bits in addressable locations
```

This is a conceptual hierarchy. The precise organization depends on the memory technology and hardware implementation.

## 9. Why RAM is volatile

RAM is generally **volatile**: it does not preserve its stored state when power is removed.

```text
Computer powered on → RAM holds active program state
Power removed       → RAM loses that state
```

This differs from an SSD, which is non-volatile and can preserve files when the computer is turned off.

## 10. RAM versus storage

A program file may persist on an SSD. When the program runs, the operating system and runtime use RAM for active code and data.

```text
SSD: persistent files
        │
        ▼
RAM: active program state and data
        │
        ▼
CPU: executes instructions and works with data
```

A useful distinction:

- **Storage** is for persistent information.
- **RAM** is working memory used while programs run.

This is a conceptual distinction; operating systems and runtimes use memory in more detailed ways.

## 11. Connection to the CPU memory hierarchy

```text
CPU
 ├─ Registers: very small and very fast
 ├─ Cache: small and fast
 ├─ RAM: larger working memory
 └─ Storage: persistent and generally much slower
```

Generally, moving down this hierarchy means capacity increases and latency increases, while cost per bit decreases. Exact performance depends on the hardware and access pattern.

## 12. A crucial distinction: value versus location

Imagine multiple locations contain the same value:

```text
Address     Data
1000        42
1001        17
1002        42
1003        99
1004        42
```

Asking for “the value `42`” does not uniquely identify which location is wanted. The system needs an address to select the particular location.

**Refined mental model:** an address identifies a location; the bits at that location represent data.

## 13. Python connection

For code such as:

```python
x = 42
```

avoid assuming that `x` is stored at a known physical RAM address. Several layers exist between Python source code and physical RAM. Later concepts will explain variables, references, Python objects, virtual addresses, and address translation.

For now, keep the broad model:

```text
Python program → process memory → memory system → physical RAM
```

Do not yet assume that a Python variable is itself a physical memory location.

## 14. AI engineering connection

A running FastAPI service, Python worker, or AI application needs memory for active program state and data. Understanding physical RAM is a foundation for later reasoning about worker memory usage, large objects, model loading, and memory limits.

Those topics depend on additional concepts—especially virtual memory, allocation, Python objects, and object lifetime—which will be studied later.

## Key takeaways

- RAM is physical working memory used by active programs.
- RAM stores bits, organized into addressable locations.
- An address identifies a location; a value is the data represented there.
- Reading retrieves data from a selected location.
- Writing stores data at a selected location.
- “Random access” means an arbitrary location can be accessed without sequentially traversing earlier locations.
- RAM is volatile; SSD storage is non-volatile.
- The CPU works with a memory hierarchy that includes registers, cache, RAM, and storage.
- A Python variable should not be equated directly with a physical RAM address.

## Common misconceptions

- **“RAM stores data” is the whole explanation.** It leaves out addressable locations and how they are accessed.
- **“The CPU asks RAM for the value 42.”** A value alone may occur at many locations; the system needs an address.
- **“Random access means unpredictable access.”** It means locations can be accessed without sequentially reading every earlier location.
- **“A Python variable is a physical address.”** That skips several layers of abstraction.
