# 00.3.04 — Pages

## 1. Why pages exist

Processes have virtual address spaces, and the operating system must manage how virtual memory is mapped to physical memory. Managing memory as one enormous block—or tracking every byte with a separate mapping—would be impractical.

Paging divides virtual memory into fixed-size blocks called **pages**. Physical memory is divided into corresponding fixed-size blocks called **frames**.

## 2. Page versus frame

- **Page:** a fixed-size block of virtual memory.
- **Physical frame:** a fixed-size block of physical RAM that can hold a page.

For a given paging arrangement, pages and frames have the same size. A page and a frame are not the same thing: one is a virtual-memory unit and the other is a physical-memory unit.

Common page sizes include 4 KB, although systems can support other sizes. This note uses 4 KB (4096 bytes) for examples.

## 3. Example: dividing a virtual address space

Suppose a simplified virtual address space is 16 KB and the page size is 4 KB.

```text
16 KB ÷ 4 KB = 4 pages
```

With addresses starting at zero, the page ranges are:

| Virtual page | Address range |
|---:|---|
| 0 | 0–4095 |
| 1 | 4096–8191 |
| 2 | 8192–12287 |
| 3 | 12288–16383 |

Each page contains 4096 bytes. Address ranges in this example are inclusive.

## 4. Virtual pages do not have to map to matching-numbered frames

A page table may record mappings such as:

```text
Virtual Page 0 → Physical Frame 5
Virtual Page 1 → Physical Frame 2
Virtual Page 2 → Physical Frame 7
Virtual Page 3 → Physical Frame 1
```

Virtual page numbers and physical frame numbers belong to different numbering systems. There is no requirement that their numbers match.

This allows the OS to map virtual pages to available physical frames without requiring all of a process's memory to occupy one contiguous physical region.

## 5. Page number and offset (basic intuition)

A virtual address can be described as:

- **Page number:** which virtual page contains the address.
- **Offset:** the position within that page, counted from the start.

For 4 KB pages, each page contains 4096 byte positions, numbered 0 through 4095.

Example: address `5000` lies in page 1 because page 1 covers addresses 4096–8191. Its offset is:

```text
5000 − 4096 = 904
```

So it is page 1, offset 904.

You do not need to master the arithmetic immediately. The important intuition is that an address identifies both a page and a position inside that page.

## 6. How an offset is preserved in a mapping

Suppose virtual page 1 maps to physical frame 2. With 4096-byte pages and zero-based frame numbering, frame 2 starts at physical address:

```text
2 × 4096 = 8192
```

Virtual address 5000 is page 1, offset 904. Its corresponding physical address is:

```text
8192 + 904 = 9096
```

The offset stays the same because the mapping replaces the virtual page with its physical frame while selecting the same position within that block.

This numerical detail is useful, but the key idea is the page-to-frame mapping. It is fine to revisit the calculations later.

## 7. Why fixed-size pages are useful

- The OS can manage memory in consistent units.
- A virtual page can map to an available physical frame.
- A process's virtual address space need not occupy one contiguous physical region.
- Address translation can use a regular, systematic structure.

A trade-off is that some allocated pages may contain unused space. This is one form of **internal fragmentation**.

## 8. Python and AI engineering connection

Python objects and runtime allocations exist within a process's virtual address space. The OS manages memory mappings in pages, but a Python object is not necessarily one page, and a page is not a Python object.

```text
Python process
      ↓
Virtual address space
      ↓
Virtual pages
      ↓
Physical frames in RAM
```

This is useful background for later understanding process memory use, large objects, worker processes, and model loading. The runtime's allocation behavior and the OS's page management are different layers.

## Key takeaways

- A page is a fixed-size block of virtual memory.
- A frame is a fixed-size block of physical RAM.
- Pages and frames have matching sizes in a given paging arrangement.
- Virtual page numbers do not need to match physical frame numbers.
- An address can be understood as a page number plus an offset within the page.
- The offset stays the same when a page is mapped to a frame.
- Paging lets virtual memory map to physical frames without requiring one contiguous physical region for the whole address space.

## Common misconceptions

- **“A page is a physical block of RAM.”** A page is virtual; a frame is physical.
- **“Virtual page 2 must map to physical frame 2.”** The numbers are independent.
- **“A page is a Python object.”** Pages and runtime objects are different abstractions.
- **“The offset changes when a page maps to a frame.”** The position within the page is preserved in the corresponding frame.
