# 00.3.05 — Page Tables

## 1. Why Page Tables Are Needed

A process works with **virtual addresses**, while physical RAM is organized using **physical frames**. The system needs a way to record which physical frame corresponds to each virtual page.

A **page table** is a data structure that records mappings from a process's virtual pages to physical frames. Page-table entries can also contain information such as whether a page is present and what access permissions apply.

## 2. Virtual Pages and Physical Frames

- **Virtual page:** A fixed-size block in a process's virtual address space.
- **Physical frame:** A fixed-size block of physical RAM.
- **Page table:** Records the mapping between virtual pages and physical frames.

Virtual page numbers and physical frame numbers are separate numbering systems. A virtual page does not have to map to a physical frame with the same number.

### Example: Process A

| Virtual page | Physical frame |
|---:|---:|
| 0 | 4 |
| 1 | 6 |
| 2 | 3 |
| 3 | 7 |

In this example, virtual page 2 maps to physical frame 3.

## 3. Each Process Has Its Own Mappings

Processes have separate virtual address spaces and their own page-table mappings.

For example:

| Process | Virtual page | Physical frame |
|---|---:|---:|
| A | 2 | 3 |
| B | 2 | 5 |

Both processes can use virtual page number 2 while mapping it to different physical frames. The same virtual page number therefore does not necessarily identify the same physical memory across processes.

The operating system manages the process's memory mappings and configures the relevant page-table structures.

## 4. How Address Translation Works

At a high level:

1. A process accesses a virtual address.
2. The memory-management unit (**MMU**) uses the page-table mapping to translate the virtual address to a physical address.
3. Hardware checks the applicable access permissions.
4. If the access is valid and permitted, memory access can proceed. If the access violates a protection rule or the mapping cannot be used, the hardware raises a fault for the operating system to handle.

The MMU does not necessarily read the page table from RAM on every access. Modern processors commonly use a **Translation Lookaside Buffer (TLB)** to cache recent address translations. Detailed TLB behavior and memory-access costs are outside the scope of this introductory note.

## 5. Page-Table Entries and Permissions

A page-table entry can contain information such as:

- **Frame mapping:** Which physical frame corresponds to the virtual page.
- **Present/valid status:** Whether the mapping is currently available for the access.
- **Access permissions:** Whether reading, writing, or executing is allowed.
- **Other hardware-management information:** Additional status or control bits used by the system.

### Example: Readable but not writable

Suppose a page is mapped and permits reading but prohibits writing. If the process tries to write to that page, the hardware blocks the prohibited access and raises a **protection fault**. The operating system handles the fault; it does not simply move the write to a different frame.

## 6. Responsibilities: Operating System vs. MMU

- **Operating system:** Manages process memory mappings, configures page tables, and handles relevant memory faults.
- **MMU and processor hardware:** Perform normal address translation and enforce memory-access permissions during execution.

The OS sets up the rules; hardware checks and applies them during ordinary memory access.

## 7. Common Misconceptions

- **Incorrect:** Virtual page 2 must map to physical frame 2.  
  **Correct:** Virtual pages and physical frames use separate numbering systems.

- **Incorrect:** If two processes use virtual page 2, they must access the same physical memory.  
  **Correct:** Their page tables can map that virtual page to different frames. Shared memory is also possible when mappings are deliberately configured to refer to shared physical memory.

- **Incorrect:** A mapped page can always be read or written.  
  **Correct:** Access permissions can restrict reading, writing, or execution.

- **Incorrect:** The OS software translates every memory access by itself.  
  **Correct:** The MMU normally performs hardware address translation using the configured mappings; the OS manages those mappings and handles faults.

## 8. Key Takeaways

1. A page table maps virtual pages to physical frames.
2. Each process has its own virtual address space and mappings.
3. The same virtual page number can map to different physical frames in different processes.
4. Page-table entries can record availability and access permissions.
5. The MMU performs normal translation and hardware permission checks.
6. Invalid or prohibited accesses can raise faults that the OS must handle.
7. The TLB caches recent translations to help avoid repeatedly consulting page tables in RAM.

## 10. Connection to Later Topics

Page tables are part of the memory-translation mechanism. Later concepts—such as memory allocation, stack and heap memory, Python objects, and memory-access costs—build on the broader idea that a program's virtual memory is managed and translated before physical memory is accessed.
