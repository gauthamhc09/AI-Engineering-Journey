# 00.3.05 — Page Tables

## Why page tables are needed
A process uses virtual addresses, while physical RAM is organized into physical frames. A **page table** records mappings from a process's virtual pages to physical frames. Entries may also contain availability and permission information.

## Virtual pages and physical frames
- **Virtual page:** A fixed-size block in a process's virtual address space.
- **Physical frame:** A fixed-size block of physical RAM.
- **Page table:** Records mappings between them.

Example:

| Virtual page | Physical frame |
|---:|---:|
| 0 | 4 |
| 1 | 6 |
| 2 | 3 |
| 3 | 7 |

Virtual page 2 maps to frame 3. Page numbers and frame numbers are separate numbering systems.

## Independent process mappings
Processes have separate virtual address spaces and page-table mappings.

| Process | Virtual page | Physical frame |
|---|---:|---:|
| A | 2 | 3 |
| B | 2 | 5 |

The same virtual page number can map to different physical frames. Shared memory is possible when mappings deliberately refer to shared physical memory.

## Address translation
1. A process accesses a virtual address.
2. The **memory-management unit (MMU)** uses the page-table mapping to translate it to a physical address.
3. Hardware checks permissions.
4. An invalid or prohibited access can raise a fault for the OS to handle.

The MMU does not necessarily read the page table from RAM on every access. A **Translation Lookaside Buffer (TLB)** commonly caches recent translations.

## Page-table entries and permissions
Entries may record:
- Physical frame mapping.
- Present/valid status.
- Read, write, and execute permissions.
- Other hardware-management status or control bits.

If a page is readable but not writable, a prohibited write raises a **protection fault**. The OS handles the fault; the write is not simply moved to another frame.

## OS vs. MMU
- **OS:** Manages mappings, configures page tables, and handles relevant faults.
- **MMU/hardware:** Performs normal address translation and enforces access permissions.

## Key takeaways
1. Page tables map virtual pages to physical frames.
2. Each process has its own virtual address space and mappings.
3. The same virtual page can map to different frames in different processes.
4. Entries can include availability and permission information.
5. The MMU performs normal translation and hardware permission checks.
6. Invalid or prohibited access can raise a fault.
7. The TLB caches recent translations.
