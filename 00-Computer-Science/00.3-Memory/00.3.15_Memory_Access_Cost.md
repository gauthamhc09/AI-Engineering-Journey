# 00.3.15 — Memory Access Cost

## Core idea
Memory accesses have different costs. Cache access is typically faster than fetching data from RAM. Performance depends on both computation and the cost/frequency of obtaining data.

## Simplified hierarchy
L1 → L2 → L3 → RAM. This is a conceptual order; a request can be satisfied at any level containing the data.

## What happens
1. The CPU needs data for an instruction.
2. It checks the relevant cache.
3. A hit supplies data from that level.
4. A miss causes lower levels to be checked; RAM may be accessed.
5. Waiting for data can stall dependent instructions, though independent work may sometimes proceed.

## Latency vs. bandwidth
- **Latency:** time for an access/request to deliver useful data.
- **Bandwidth:** amount of data transferred per unit time.
A workload can be limited by latency, bandwidth, computation, or a combination.

## Sequential vs. random access
Sequential access to a large contiguous numerical array tends to benefit from spatial locality. A fetched cache line brings adjacent bytes, so later accesses may hit in cache. Random access across distant locations may have poorer locality and more misses.

```python
# Sequential pattern
for i in range(len(numbers)):
    process(numbers[i])

# Irregular pattern
for i in random_indices:
    process(numbers[i])
```
If `numbers` is a large contiguous numerical array, the sequential pattern may use cache lines more effectively. Actual performance depends on implementation and workload; Python overhead also matters.

## AI connection
Tensors, embeddings, and model weights are affected by memory hierarchy and data layout. Optimization can mean reducing unnecessary data movement and improving locality, not just reducing arithmetic.

## Misconceptions
Every L1 miss goes to RAM — no. Every access costs the same — no. Every miss stalls the entire CPU — not necessarily. Sequential access is always faster — not guaranteed. Latency and bandwidth are not synonyms.
