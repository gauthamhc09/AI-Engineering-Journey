# 00.3.03 — Virtual Addresses

## 1. Definition

A **virtual address** identifies a location within a process's virtual address space. Programs normally use virtual addresses rather than directly addressing arbitrary physical RAM locations.

A virtual address and a physical address are different kinds of addresses, even though both may be represented as numbers.

```text
Program / process
      ↓
Virtual address
      ↓
Address translation
      ↓
Physical address
      ↓
Physical memory
```

## 2. Address versus value

An address identifies a location; it does not tell us the value stored there.

```text
Virtual address     Example data
0x1000              42
0x1004              99
0x1008              17
```

These are illustrative examples. The exact relationship between program variables, objects, and addresses depends on the runtime and memory layout.

## 3. Why virtual addresses are useful

Each process has its own virtual address space. The same numerical virtual address can map to different physical locations in different processes.

```text
Process A: Virtual 0x1000 → Physical 0x5000
Process B: Virtual 0x1000 → Physical 0x9000
```

Therefore, a virtual address by itself does not uniquely identify a physical location. The relevant address-space mapping also matters.

## 4. Address translation: roles

- **Process/program:** uses virtual addresses when executing memory-accessing instructions.
- **Operating system:** configures and manages memory mappings and permissions.
- **MMU (Memory Management Unit):** hardware that participates in address translation and memory-access protection.
- **Physical memory:** the hardware location ultimately accessed when the mapping is valid and the access is permitted.

The OS does not manually translate every ordinary memory access in software. Hardware performs the usual translation using the configured memory-management structures.

## 5. Address ranges and validity

A process has a range of possible virtual addresses. However, having a numerical virtual address does not guarantee that the address is mapped, allocated, resident in RAM, or accessible.

An access to an unmapped or prohibited address may raise an exception. An access to a valid but non-resident page may trigger a page fault that the OS handles.

Detailed paging and page-fault mechanisms are covered in later concepts.

## 6. Python connection

For:

```python
x = 42
```

do not assume that `x` itself is a physical RAM address. Python executes inside a process and uses the process's virtual address space. The relationship between Python variables, references, and objects will be covered later.

High-level model:

```text
Python program
      ↓
Python runtime and process memory
      ↓
Virtual address space
      ↓
Address translation
      ↓
Physical memory
```

## 7. AI engineering connection

FastAPI services, Python workers, and AI applications execute within process virtual address spaces. This helps explain how processes have separate memory views and why the system can manage memory mappings independently of where data resides physically.

GPU memory and model-serving details require additional concepts and are outside the scope of this lesson.

## Key takeaways

- A virtual address identifies a location in a process's virtual address space.
- A physical address identifies a location in physical memory.
- The same virtual address can map to different physical addresses in different processes.
- The OS configures mappings and permissions; the MMU participates in hardware translation and protection.
- A virtual address alone does not guarantee a valid or resident memory location.
- An address identifies a location, not the value stored there.

## Common misconceptions

- **“The OS translates every access itself.”** The OS manages the mappings; hardware normally performs address translation.
- **“A virtual address is a physical address.”** Translation separates the two.
- **“Every virtual address is valid and backed by resident RAM.”** Mappings and permissions determine whether access is valid; residency can vary.
- **“A Python variable is a physical address.”** This skips the Python runtime and virtual-memory abstractions.
