# 00.3.14 — CPU Cache and Locality

## Why caches exist
CPUs can execute instructions faster than RAM can always deliver data. CPU caches are small, fast structures that keep copies of recently or predictably needed data and instructions.

## Simplified hierarchy
- **L1:** very small, typically fastest; often split into instruction/data caches.
- **L2:** larger, typically slower than L1.
- **L3:** often larger and shared; typically slower than L1/L2.
- **RAM:** much larger, usually higher latency.
Exact designs vary by processor.

## Hits and misses
- **Cache hit:** data is present at the cache level being checked.
- **Cache miss:** data is absent there, so lower levels are checked and RAM may be accessed.
An L1 miss does not automatically mean a RAM access.

## Temporal locality
Recently accessed data or instructions are likely to be used again soon.

## Spatial locality
Nearby memory locations are likely to be accessed soon after one location is accessed.

## Cache lines
Caches transfer data in blocks called **cache lines**, not one byte at a time. A common size is 64 bytes, but this is not universal. Fetching one line brings nearby bytes together. Hardware prefetching is related but distinct: it may fetch additional lines in anticipation of future accesses.

## Python nuance
A CPython list stores references in a contiguous array, but referenced Python objects may be elsewhere in memory. NumPy arrays can store numerical values compactly and contiguously, which often supports efficient native loops.

## Why locality matters
Sequential access to a contiguous array can use nearby bytes already brought into cache. Irregular access can cause more misses. Performance also depends on cache capacity, prefetching, data layout, and workload.

## AI connection
Tensors, embeddings, model weights, and numerical datasets are affected by data layout and access patterns. Contiguous data and reuse can improve cache utilization.

## Misconceptions
Every miss reaches RAM — no. Cache data is permanent — no. Nearby Python objects are always adjacent — no. Cache-line fetching and prefetching are identical — no.
