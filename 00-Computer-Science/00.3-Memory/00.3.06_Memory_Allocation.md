# 00.3.06 — Memory Allocation

## Definition
**Memory allocation** is the process of obtaining or reserving memory for a program or its runtime to use.

```python
name = "Gautham"
scores = [85, 90, 95]
user = {"name": name, "active": True}
```

## Allocation happens at multiple layers
1. **Python code:** Creates objects or requests data structures.
2. **Python runtime / allocator:** Manages memory for Python objects and may reuse memory it already controls.
3. **Operating system:** Provides and manages virtual memory for the process.
4. **Physical memory/backing resources:** Physical RAM may back virtual pages as they are used.

This is a simplified layered model, not a claim that every object allocation triggers an OS request.

## Example
```python
scores = [85, 90, 95]
```
At a high level, Python creates a list object and allocates the memory it needs; the list stores references to its elements; Python's runtime manages object memory; and the OS manages the process's virtual memory and mappings.

Python's allocator may satisfy a request using memory it already manages. Creating a list does not necessarily require a fresh OS request.

## Python allocator vs. OS
- **Python allocator:** Manages memory used by Python objects and may reuse memory it controls.
- **OS:** Manages the process's virtual address space, mappings, permissions, and system-wide resources.

The OS does not necessarily provide one single block for the entire Python heap. Also, allocated virtual memory does not guarantee that every corresponding page is already resident in physical RAM.

## Common misconceptions
- Every Python list creation requires a new OS request — **false**; the allocator may reuse managed memory.
- The Python heap must be one single block from the OS — **false**; memory may be managed through different mechanisms.
- Allocated virtual memory guarantees immediate RAM residency — **false**; virtual allocation and physical residency are distinct.

## Key takeaways
1. Allocation obtains or reserves memory for use.
2. It happens at multiple layers.
3. Python's allocator can reuse memory it already manages.
4. The OS manages process virtual memory and its relationship with physical memory.
5. Virtual allocation does not necessarily mean immediate physical residency.
