# Module 00.6.15 — Tries (Prefix Trees)

## 1. Why do we need a Trie?
Suppose an application stores many words and must suggest matches as a user types. A simple solution is to scan a list and call `startswith()` on every word. This works, but repeated scans can be expensive for large collections.

A **Trie** organizes strings so that words with common prefixes share paths.

## 2. What is a Trie?
A Trie (pronounced “try”) is a tree-based data structure for storing strings by their prefixes.

- **Root:** starting node; usually represents no character.
- **Child node:** represents the next character in a path.
- **End-of-word marker:** indicates that a complete word ends at that node.

For `cat`, `car`, `care`, and `cake`, the prefix `ca` is shared. The `r` node can mark the end of `car` and also have a child `e` for `care`. A node can therefore end one word and be a prefix of a longer word.

## 3. Basic Trie node

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end_of_word = False
```

- `children` maps the next character to its child node.
- `is_end_of_word` records whether a complete word ends here.

## 4. Create a Trie

```python
class Trie:
    def __init__(self):
        self.root = TrieNode()
```

The root is the entry point to the structure.

## 5. Insert a word
For each character, reuse an existing child if it exists; otherwise create one. Move to that child. After the final character, mark the node as a complete word.

```python
def insert(self, word):
    current = self.root

    for char in word:
        if char not in current.children:
            current.children[char] = TrieNode()

        current = current.children[char]

    current.is_end_of_word = True
```

Inserting `care` after `car` reuses the `c → a → r` path and adds `e`.

## 6. Search for a complete word
Follow each character. If a child is missing, return `False`. If the path exists, check the final node's end-of-word marker.

```python
def search(self, word):
    current = self.root

    for char in word:
        if char not in current.children:
            return False
        current = current.children[char]

    return current.is_end_of_word
```

Reaching a path is not enough: it may only be a prefix.

## 7. Check a prefix
`starts_with()` checks whether the prefix path exists. It does not require the final node to mark a complete word.

```python
def starts_with(self, prefix):
    current = self.root

    for char in prefix:
        if char not in current.children:
            return False
        current = current.children[char]

    return True
```

If `car` is inserted but `ca` is not:
- `search("ca")` → `False`
- `starts_with("ca")` → `True`

## 8. Complete basic implementation

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end_of_word = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        current = self.root
        for char in word:
            if char not in current.children:
                current.children[char] = TrieNode()
            current = current.children[char]
        current.is_end_of_word = True

    def search(self, word):
        current = self.root
        for char in word:
            if char not in current.children:
                return False
            current = current.children[char]
        return current.is_end_of_word

    def starts_with(self, prefix):
        current = self.root
        for char in prefix:
            if char not in current.children:
                return False
            current = current.children[char]
        return True


trie = Trie()
for word in ["cat", "car", "care", "cake"]:
    trie.insert(word)

print(trie.search("car"))       # True
print(trie.search("care"))      # True
print(trie.search("cab"))       # False
print(trie.starts_with("ca"))   # True
print(trie.starts_with("car"))  # True
print(trie.starts_with("cab"))  # False
```

## 9. Autocomplete using DFS
To retrieve all words beginning with a prefix:
1. Find the node representing the prefix.
2. Traverse its descendants.
3. Whenever a node marks the end of a word, add the current path to the results.

Find the prefix node:

```python
def find_node(self, prefix):
    current = self.root

    for char in prefix:
        if char not in current.children:
            return None
        current = current.children[char]

    return current
```

Collect complete words below that node:

```python
def collect_words(self, node, prefix, results):
    if node.is_end_of_word:
        results.append(prefix)

    for char, child in node.children.items():
        self.collect_words(child, prefix + char, results)
```

This is recursive Depth-First Search (DFS): explore one child path deeply, then backtrack to explore other children.

Autocomplete method:

```python
def autocomplete(self, prefix):
    node = self.find_node(prefix)

    if node is None:
        return []

    results = []
    self.collect_words(node, prefix, results)
    return results
```

Complete example:

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end_of_word = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        current = self.root
        for char in word:
            if char not in current.children:
                current.children[char] = TrieNode()
            current = current.children[char]
        current.is_end_of_word = True

    def find_node(self, prefix):
        current = self.root
        for char in prefix:
            if char not in current.children:
                return None
            current = current.children[char]
        return current

    def collect_words(self, node, prefix, results):
        if node.is_end_of_word:
            results.append(prefix)
        for char, child in node.children.items():
            self.collect_words(child, prefix + char, results)

    def autocomplete(self, prefix):
        node = self.find_node(prefix)
        if node is None:
            return []
        results = []
        self.collect_words(node, prefix, results)
        return results


trie = Trie()
for word in ["cat", "car", "care", "cake", "dog", "door"]:
    trie.insert(word)

print(trie.autocomplete("ca"))
# ['cat', 'car', 'care', 'cake']

print(trie.autocomplete("do"))
# ['dog', 'door']

print(trie.autocomplete("xyz"))
# []
```

Suggestion order depends on child iteration order and insertion history in this implementation. Production systems may rank suggestions separately.

## 10. Time and space complexity
Let L be the length of the word or prefix.

| Operation | Time |
|---|---:|
| Insert | O(L) |
| Exact search | O(L) |
| Prefix lookup | O(L) |

These bounds assume average O(1) dictionary child lookup per character.

For autocomplete:
- Finding the prefix node: O(P), where P is prefix length.
- Traversing the matching subtree: depends on the number of nodes explored.
- Building results: proportional to the output size.

A useful approximation is O(P + V_s + S), where V_s is the number of nodes explored in the matching subtree and S is the total number of characters returned.

Space can be up to O(N × L) nodes for N words of maximum length L, although shared prefixes reduce the number of nodes required.

## 11. Limitations and optimizations

### Memory overhead
Each node may contain a dictionary and an end-of-word flag. Tries can consume more memory than a list or hash table, especially when stored words share few prefixes.

### Compressed Tries
A compressed Trie combines chains of single-child character nodes into edges labelled with multiple characters. This reduces node overhead, but insertion, deletion, and prefix matching become more complex. Radix trees and Patricia tries are related compressed Trie structures.

### Character representation and normalization
Case, Unicode, punctuation, and whitespace handling depend on application requirements. For simple case-insensitive matching, normalize consistently before insertion and searching:

```python
word = word.lower()
```

Real applications may require more careful Unicode normalization.

### Autocomplete ranking
A basic Trie retrieves prefix matches but does not decide which suggestions are most useful. Production systems may rank candidates using search frequency, popularity, recency, user history, or context.

## 12. Trie vs other data structures

| Data structure | Typical strength |
|---|---|
| List | Ordered collection and sequential access |
| Hash table / dictionary | Exact key lookup |
| Set | Unique elements and membership |
| Binary Search Tree | Ordered data and range queries |
| Trie | Prefix-based string lookup |
| Graph | Complex relationships and connections |

A hash table is well suited to exact-key lookup, but it does not naturally retrieve all keys sharing a prefix. A Trie follows the prefix path directly and can traverse the matching subtree.

## 13. AI and software engineering connections

Tries can support:
- Search-box autocomplete.
- Dictionary and spell-checking tools.
- Code-editor suggestions.
- Exact prefix lookup over tokens or identifiers.

Distinguish the retrieval problem:
| Requirement | Suitable approach |
|---|---|
| Find words beginning with `mach` | Trie |
| Find a document by exact ID | Hash table / database index |
| Find semantically similar documents | Embeddings and vector search |
| Explore relationships between entities | Graph |

A Trie does not understand that `car` and `automobile` have similar meanings. It performs character-prefix matching, not semantic retrieval.

## 14. Key takeaways
- A Trie stores strings through shared prefixes.
- Each node has child links and an end-of-word marker.
- A node can mark the end of one word and still have children.
- Insert, exact search, and prefix lookup take O(L) time under average dictionary lookup assumptions.
- Autocomplete can locate a prefix node and use DFS to collect words below it.
- Tries trade memory for efficient prefix operations.
- Compressed Tries reduce node overhead by combining character paths.
- Production autocomplete often needs ranking in addition to prefix retrieval.
- Tries perform exact prefix matching, not semantic search.
