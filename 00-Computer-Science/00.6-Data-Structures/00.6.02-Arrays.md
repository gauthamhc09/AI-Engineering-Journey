# Module 00.6.02 — Arrays

## 1. What is an array?

An array is a sequence of elements that can be accessed by index. In a conventional array with fixed-size elements, the elements occupy consecutive memory locations.

Arrays are useful when a program needs ordered data and efficient access by position.

## 2. How indexing works

Suppose an array starts at address 1000 and each element occupies 4 bytes:

| Index | Illustrative address | Value |
|---:|---:|---:|
| 0 | 1000 | 10 |
| 1 | 1004 | 20 |
| 2 | 1008 | 30 |
| 3 | 1012 | 40 |

The address of an element can be calculated directly:

`Address(i) = Base address + i × Element size`

For index 3:

`1000 + 3 × 4 = 1012`

This assumes a conventional array with fixed-size elements. The computer does not need to scan earlier elements to locate the requested index.

## 3. Time complexity

- **Access by index:** O(1), because the address can be calculated directly.
- **Search in an unsorted array:** O(N) in the worst case, because elements may need to be checked one by one.
- **Update by index:** O(1) for a normal indexed assignment.
- **Insert at the beginning or middle:** O(N) in the worst case when elements must shift.
- **Delete from the beginning or middle:** O(N) in the worst case when order must be preserved and elements must shift.
- **Append with spare capacity:** O(1) for that insertion, assuming capacity is already allocated.

Big O describes growth in work, not exact elapsed time. Cache behavior and other hardware effects can affect actual latency.

## 4. Why insertion can be expensive

For an array containing:

`[10, 20, 30, 40, 50]`

Inserting `25` at index 2 while preserving order requires moving the later elements to make room:

`[10, 20, 25, 30, 40, 50]`

In the worst case, insertion near the beginning shifts many elements, producing O(N) work.

Appending to the end is different. If an unused slot is already available, no existing elements need to shift, so the insertion itself is O(1). If the array is full, resizing may require O(N) work.

## 5. Memory layout and cache locality

Consecutive storage can improve spatial locality. When the CPU fetches data from memory, it often brings a block of nearby memory into cache. Sequentially processing contiguous elements can therefore be efficient.

This can matter when processing numerical collections, including batches of features or embedding values. The benefit depends on the actual representation and implementation.

## 6. Arrays versus Python lists

A conventional array and a Python list are related concepts but are not identical.

A Python list is a dynamic array of **references to Python objects**. The objects themselves need not be stored next to one another. Python lists can hold different object types and grow dynamically.

Example:

```python
numbers = [10, 20, 30, 40, 50]

print(numbers[3])  # 40

numbers[2] = 25
print(numbers)     # [10, 20, 25, 40, 50]
```

Python list indexing is typically O(1), but list insertion and growth have their own costs. Those details are covered in the Python Lists topic.

## AI engineering connection

Arrays and array-like structures are useful for ordered numerical data and repeated indexed access. For large numerical workloads, specialized representations such as NumPy arrays may be more appropriate than a Python list of object references.

## Key takeaways

- Conventional arrays provide direct indexed access in O(1).
- Searching an unsorted array is O(N) in the worst case.
- Insertion/deletion near the beginning or middle can require shifting elements: O(N).
- Appending with available capacity can be O(1).
- Contiguous storage can improve cache locality.
- A Python list is a dynamic array of references, not a low-level array of inline integer values.
