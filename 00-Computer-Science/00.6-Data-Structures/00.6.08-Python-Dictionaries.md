# Module 00.6.08 — Python Dictionaries

## 1. What is a dictionary?
A Python dictionary is a mutable mapping of **unique, hashable keys** to values.

```python
person = {"name": "Asha", "role": "AI Engineer", "experience_years": 3}
```

Use a dictionary when you need to retrieve a value by key rather than numeric position. Values can be objects of many types, including lists and nested dictionaries. Python dictionaries preserve insertion order but do not automatically sort keys.

## 2. Creating dictionaries
```python
empty = {}
also_empty = dict()
config = {"temperature": 0.7, "max_tokens": 500}
```
`{}` creates an empty dictionary, not an empty set. Use `set()` for an empty set.

## 3. Reading values safely
```python
config = {"temperature": 0.7, "max_tokens": 500}
temperature = config["temperature"]       # 0.7
missing = config.get("timeout")            # None
timeout = config.get("timeout", 30)        # 30
```
- `d[key]` raises `KeyError` if the key is absent.
- `d.get(key)` returns `None` by default if the key is absent.
- `d.get(key, default)` returns the default without inserting the key.

To distinguish an absent key from a key mapped to `None`, use `"timeout" in config`.

## 4. Adding, updating, and deleting
```python
settings = {"theme": "dark"}
settings["language"] = "en"       # Add
settings["theme"] = "light"       # Update
settings.update({"timeout": 30})  # Add/update multiple entries
del settings["language"]          # Delete; KeyError if absent
timeout = settings.pop("timeout") # Remove and return
settings.clear()                  # Remove all entries
```
Use `pop(key, default)` if absence is expected.

### `setdefault()`
```python
counts = {}
counts.setdefault("python", 0)
counts["python"] += 1
```
`setdefault(key, default)` inserts the default only if the key is missing and returns its value. The default expression is evaluated before the call, even if the key already exists.

## 5. Membership and iteration
```python
"temperature" in config  # Checks keys
500 in config            # Checks keys, not values
500 in config.values()   # Checks values
```
```python
for key, value in config.items():
    print(key, value)
```
`keys()`, `values()`, and `items()` are dynamic views that reflect dictionary changes. Avoid structurally modifying a dictionary while iterating over it. Safer options include building a new dictionary with a comprehension or iterating over `list(config.keys())`.

## 6. Dictionary comprehensions
```python
squares = {n: n * n for n in range(5)}
active = {key: value for key, value in config.items() if value}
```
Comprehensions transform or filter mappings.

## 7. Copying and aliasing
```python
a = {"temperature": 0.7}
b = a
b["temperature"] = 0.2  # a changes too: same dictionary

c = a.copy()
c["temperature"] = 0.9  # a's top-level value remains unchanged
```
`copy()` is a **shallow copy**. Nested mutable objects remain shared:
```python
a = {"limits": {"max_tokens": 500}}
b = a.copy()
b["limits"]["max_tokens"] = 1000  # Also changes a's nested dictionary
```
Use `copy.deepcopy()` when an independent copy of nested mutable objects is appropriate.

## 8. Merging dictionaries
```python
defaults = {"temperature": 0.7, "max_tokens": 500}
user_config = {"temperature": 0.2}
config = defaults | user_config
# {'temperature': 0.2, 'max_tokens': 500}
```
- `a | b` (Python 3.9+) creates a new dictionary.
- For duplicate keys, the right-hand value wins.
- `{**a, **b}` provides the same rightmost precedence.
- `a.update(b)` mutates `a` in place.

```python
config["max_tokens"] = 1000
# defaults["max_tokens"] remains 500
```
These are shallow merges; nested dictionaries are not automatically merged recursively.

## 9. Mutable default-argument pitfall
Avoid mutable dictionary defaults when each function call should have independent state.

```python
# Risky: the same dictionary is reused across calls.
def add_setting(key, value, settings={}):
    settings[key] = value
    return settings

# Safer:
def add_setting(key, value, settings=None):
    if settings is None:
        settings = {}
    settings[key] = value
    return settings
```

## 10. Complexity and practical choices
Dictionary lookup, insertion, and deletion are typically **O(1) on average**, with worst-case behavior that can reach O(n). Resizing can make an individual insertion expensive, even though insertion is amortized O(1) in typical use.

- Use a dictionary for key-to-value lookup.
- Use a list when sequence order and duplicates matter.
- Use a set for unique elements and membership testing.
- Use a database or shared infrastructure when data must persist or be shared reliably between workers.

## 11. AI/LLM engineering connections
Dictionaries commonly represent model configuration, API request/response payloads, RAG document metadata, intermediate results keyed by IDs, and structured data passed between application layers. A Python dictionary is in-memory: it is not a database and does not perform semantic search.

## 12. Key takeaways
1. A dictionary maps unique, hashable keys to values.
2. `d[key]` raises `KeyError` for a missing key; `get()` supports defaults.
3. `in` checks keys by default.
4. Dictionaries preserve insertion order but are not automatically sorted.
5. Assignment creates an alias; `copy()` is shallow.
6. `a | b` creates a merged dictionary, with the right side winning duplicate keys.
7. `update()` mutates in place.
8. Typical key operations are O(1) on average.
9. Dictionaries support exact key lookup, not semantic similarity search.
