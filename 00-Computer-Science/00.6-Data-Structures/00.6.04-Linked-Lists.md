# Module 00.6.04 — Linked Lists

## 1. Why linked lists exist

A conventional array stores elements in consecutive memory slots. Inserting near the beginning while preserving order can require shifting many elements.

A linked list represents a sequence using separate **nodes**. Each node stores a value and one or more references linking it to other nodes. In a singly linked list, each node stores a reference to the next node.

## 2. Singly linked-list model

A singly linked list might look like:

`head → [10 | next] → [20 | next] → [30 | None]`

The **head** is a reference to the first node. The final node's `next` reference is `None`.

The logical order comes from following links. Nodes do not have to occupy consecutive physical memory locations.

## 3. Memory and references

A node typically contains:
- A value or reference to a value.
- A reference to the next node.

Because nodes may be separately allocated, linked lists can have poorer CPU cache locality than contiguous arrays. Each node also incurs link and node-object overhead.

The physical placement of nodes does not determine their logical order; the references do.

## 4. Traversal and access

To find a value, begin at the head and follow `next` references until the value is found or the list ends.

- Access by index: O(N) in the usual singly linked-list implementation.
- Search by value: O(N) in the worst case.
- Traversal of all nodes: O(N).

Unlike an array, a singly linked list generally cannot calculate the address of the element at index `i` directly.

## 5. Insertion after a known node

Suppose the list is:

`10 → 20 → 30`

To insert `25` immediately after the node containing `20`:

1. Create a node containing `25`.
2. Set `25.next` to the node containing `30`.
3. Set `20.next` to the new node containing `25`.

The resulting sequence is:

`10 → 20 → 25 → 30`

No existing nodes need to shift. If the reference to the preceding node is already available, the insertion itself is O(1).

Set the new node's `next` reference before changing the preceding node's link, so the remainder of the list is not lost.

## 6. Finding the position changes the total cost

If the node containing `20` is already known, inserting `25` after it takes O(1) time.

If only the head reference is available, the program may need to traverse the list to find `20`. Finding the node takes O(N) in the worst case, while the insertion itself is O(1).

Therefore, the overall operation is:

`O(N) + O(1) = O(N)`

Always analyze the entire operation, including locating the target position.

## 7. Typical complexity comparison

| Operation | Array / Python list | Singly linked list |
|---|---:|---:|
| Access by index | O(1) | O(N) |
| Search by value | O(N) | O(N) |
| Insert at beginning | O(N) for a Python list | O(1) with head reference |
| Insert after a known node | May require shifting; O(N) in the general array/list case | O(1) |
| Extra storage | Depends on representation | Node and link overhead |

These are typical bounds under standard assumptions. A linked list is not universally better: it trades indexed access and locality for flexible linking and efficient updates when node references are already available.

## 8. Small Python implementation

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None


first = Node(10)
second = Node(20)
third = Node(30)

first.next = second
second.next = third

current = first

while current is not None:
    print(current.value)
    current = current.next
```

Output:

```text
10
20
30
```

The traversal follows references until `current` becomes `None`.

Python's built-in `list` is not a linked list; it is a dynamic array of references. For efficient operations at both ends in Python, `collections.deque` is often a more practical choice than implementing a linked list manually.

## AI engineering connection

Linked lists illustrate how a representation can make particular updates efficient, but they are not automatically the best structure for AI pipelines. Select a structure based on actual operations, locality, memory overhead, and implementation requirements.

## Key takeaways

- A singly linked list consists of nodes connected by `next` references.
- Nodes need not be stored in consecutive memory locations.
- Access by index and search generally take O(N).
- Insertion after a known node takes O(1).
- Finding the insertion point can still take O(N).
- Linked lists have extra node/link overhead and often poorer cache locality than contiguous storage.
- Python's built-in list is not a linked list.
