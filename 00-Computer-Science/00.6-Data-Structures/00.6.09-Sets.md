# Module 00.6.09 — Sets

## 1. What is a set?
A Python set is a mutable collection of **unique, hashable elements**.

```python
words = ["python", "ai", "python", "llm", "ai", "data"]
unique_words = set(words)
# {'python', 'ai', 'llm', 'data'}; display/iteration order may vary
```
Sets automatically eliminate duplicates. They are designed for uniqueness, set operations, and membership testing—not positional access.

## 2. Creating sets
```python
languages = {"Python", "Java", "Go"}
unique_numbers = set([1, 2, 2, 3])  # {1, 2, 3}
empty_set = set()
empty_dict = {}  # Important: {} is a dictionary, not a set.
```

## 3. Membership testing and complexity
```python
languages = {"Python", "Java", "Go"}
print("Python" in languages)  # True
```
Set membership is typically **O(1) on average** because Python sets use a hash-table-based implementation. List membership is O(n) in the worst case because elements may be checked one by one.

| Operation | Typical complexity |
|---|---:|
| `x in some_set` | O(1) average |
| `some_set.add(x)` | O(1) average |
| `some_set.remove(x)` / `discard(x)` | O(1) average |
| Membership in a list | O(n) |
| Worst-case set membership/update | Can be O(n) |

These are average-case expectations, not guarantees for every input.

## 4. Why elements must be hashable
Each set element needs a stable hash value and equality behavior suitable for membership checks.

```python
valid = {10, "Python", (1, 2)}
```
Lists and dictionaries are unhashable and cannot be direct set elements:
```python
# TypeError: list is unhashable
# invalid = {[1, 2], [3, 4]}
```
A tuple is hashable only if all its elements are hashable:
```python
valid = {(1, 2), (3, 4)}
# TypeError: tuple contains an unhashable list
# invalid = {(1, [2, 3])}
```

## 5. Set operations
```python
document_a = {"python", "ai", "data"}
document_b = {"ai", "llm", "data"}
```
- **Union (`|`)**: elements in either set.
  ```python
  document_a | document_b  # {'python', 'ai', 'data', 'llm'}
  ```
- **Intersection (`&`)**: elements in both sets.
  ```python
  document_a & document_b  # {'ai', 'data'}
  ```
- **Difference (`-`)**: elements in the left set but not the right. Direction matters.
  ```python
  document_a - document_b  # {'python'}
  document_b - document_a  # {'llm'}
  ```
- **Symmetric difference (`^`)**: elements in either set but not both.
  ```python
  document_a ^ document_b  # {'python', 'llm'}
  ```
Named methods are also available: `.union()`, `.intersection()`, `.difference()`, and `.symmetric_difference()`.

## 6. Subsets and supersets
```python
required = {"python", "ai"}
available = {"python", "ai", "llm"}

required <= available  # True: required is a subset
available >= required  # True: available is a superset
```
These relationships can validate required capabilities, permissions, or feature sets.

## 7. Adding and removing elements
```python
skills = {"python", "sql"}
skills.add("fastapi")          # Add one
skills.update(["ai", "sql"])   # Add many; duplicates ignored
skills.discard("java")         # No error if absent
skills.remove("sql")           # Raises KeyError if absent
```
- `discard(x)` does nothing if `x` is absent.
- `remove(x)` raises `KeyError` if `x` is absent.
- `clear()` removes all elements.
- `copy()` creates a shallow copy.
- Sets do not provide list-style numeric indexing; do not rely on iteration order.

## 8. Set vs list vs dictionary
| Need | Good starting choice |
|---|---|
| Preserve sequence order and allow duplicates | `list` |
| Map unique keys to values | `dict` |
| Track unique elements and test membership | `set` |
| Count occurrences | `collections.Counter` or a dictionary of counts |

## 9. AI/LLM engineering connections
### Deduplicating IDs
```python
unique_ids = set(document_ids)
```

### Finding newly arriving documents
```python
processed = {"doc_101", "doc_102", "doc_103"}
incoming = {"doc_102", "doc_103", "doc_104", "doc_105"}
new_documents = incoming - processed
# {'doc_104', 'doc_105'}
```
This can help a RAG ingestion pipeline identify IDs not previously seen in an in-memory set. Concurrent workers, restarts, and distributed execution may require persistent state and coordination.

### Finding missing permissions
```python
missing_permissions = required_permissions - granted_permissions
```

**Limitation:** Sets perform exact membership checks. They do not know that differently worded sentences have the same meaning. Semantic retrieval typically requires embeddings and vector search.

## 10. Common pitfalls
- `{}` is an empty dictionary; use `set()` for an empty set.
- Elements must be hashable.
- Sets eliminate duplicates and do not provide positional indexing.
- Do not rely on iteration order.
- Average O(1) membership is not a worst-case guarantee.
- Use a list if ordering or repeated occurrences matter.
- Use a counter if frequency matters.

## 11. Key takeaways
1. A set stores unique, hashable elements.
2. Membership is typically O(1) on average.
3. `|` is union, `&` intersection, `-` difference, and `^` symmetric difference.
4. Difference is directional: `A - B` is not generally equal to `B - A`.
5. Sets are useful for deduplication and exact membership checks.
6. An in-memory set alone does not guarantee durable or distributed deduplication.
