# Module 00.6.01 — Why Data Structures

## 1. Why data structures exist

A program often needs to store, retrieve, update, insert, delete, and search data. The way data is organized affects how efficiently these operations can be performed.

For example, an AI application may process hundreds of thousands of document chunks. It might need to retrieve chunks by ID, deduplicate incoming documents, update metadata, or iterate over a collection. Different data structures make these operations more or less efficient.

**A data structure is a way of organizing and representing data so that particular operations can be performed efficiently and correctly.**

## 2. Important operations

- **Access:** Retrieve an element, often by position or key.
- **Search:** Find a particular value.
- **Insertion:** Add new data.
- **Deletion:** Remove data.
- **Traversal:** Visit elements in a collection.
- **Memory usage:** Account for the storage required by the representation.

No single data structure is best for every operation. A structure that supports fast lookup may use more memory or have other trade-offs.

## 3. Connection to memory and Big O

RAM provides storage for data while a program runs, but it does not determine how the program organizes that data. The representation affects how the program locates and manipulates values.

Big O describes how an operation's work grows as the input size grows. It describes asymptotic growth, not exact elapsed time.

For example:

- A sequential search through an unsorted collection takes **O(N)** time in the worst case.
- A hash table typically supports expected **O(1)** lookup under normal hashing assumptions, though worst-case lookup can be **O(N)**.

These are different ways to organize and locate data, not guarantees of exact runtime.

## 4. Example: checking processed document IDs

```python
document_ids = [
    "doc_101",
    "doc_205",
    "doc_310",
    "doc_415",
]

target = "doc_310"

for document_id in document_ids:
    if document_id == target:
        print("Document found")
        break
```

This is sequential search. In the worst case, it examines all N elements: **O(N)**.

If the application repeatedly checks whether IDs exist, a set may be a better fit:

```python
document_ids = {
    "doc_101",
    "doc_205",
    "doc_310",
    "doc_415",
}

print("doc_310" in document_ids)
```

Python sets typically provide expected **O(1)** membership checks, while worst-case membership can be **O(N)**. Sets also maintain unique elements.

In a RAG ingestion pipeline, a set can help track processed IDs and avoid duplicate work. It does not, by itself, perform semantic retrieval of document content.

## 5. Abstract data structure vs. implementation

An abstract data structure describes the organization or behavior required. An implementation is the concrete way it is built.

For example, a **stack** describes last-in, first-out (LIFO) behavior. A Python list can implement a stack using `append()` and `pop()`, but another implementation could use linked nodes. The abstract behavior is similar, while memory usage and operation costs can differ.

## 6. Choosing a structure

Consider the operations your application performs most often and the trade-offs you can accept:

- Access versus insertion/deletion.
- Search speed versus memory usage.
- Contiguous storage versus linked nodes.
- Ordering versus fast membership checks.
- Average/expected-case versus worst-case performance.
- Implementation overhead and real workload patterns.

A data structure is not universally best; its suitability depends on the workload and implementation.

## Key takeaways

- Data structures organize data to support operations efficiently and correctly.
- Representation affects operation costs and memory behavior.
- Big O describes growth as input size increases, not exact time.
- Python sets are useful for uniqueness and expected-fast membership checks.
- Always choose a structure based on actual operations and trade-offs.
