# Module 00.6.03 — Python Lists

## 1. Why Python lists exist

Python lists provide a dynamic, ordered collection that can grow or shrink as needed. They are convenient when the number of items is not known in advance, such as document chunks collected during a RAG ingestion pipeline.

```python
chunks = ["chunk A", "chunk B", "chunk C"]
chunks.append("chunk D")
chunks.append("chunk E")
```

Python manages the storage needed as the list grows.

## 2. A Python list stores references

A Python list stores a sequence of references to Python objects. The referenced objects themselves need not be stored next to each other in memory.

```python
items = [10, "hello", 3.14, True]
```

A list can hold references to objects of different types.

This differs from a conventional low-level array of fixed-width integers, which can store integer values inline in a contiguous block.

## 3. Dynamic capacity and resizing

Python lists generally allocate more reference slots than their current length requires. This extra capacity allows some append operations to happen without resizing.

When capacity is exhausted, an implementation may allocate a larger reference array and transfer the existing references to it. The referenced Python objects generally do not need to be recreated merely because the list's reference array was resized.

The exact allocation policy is implementation-dependent.

## 4. Why append is amortized O(1)

Most `append()` operations put a reference into an available slot and update the list length, taking O(1) time under the usual model.

Occasionally, an append triggers resizing and copying of references, which can take O(N) time for that operation.

Because resizing is infrequent under a dynamic-array growth strategy, the cost spread across a long sequence of appends is **amortized O(1)** per append.

Amortized O(1) does not mean every append takes constant time. An individual append can take O(N) when resizing is required.

## 5. Common list operation costs

| Operation | Typical complexity |
|---|---:|
| Index access, `items[i]` | O(1) |
| Append, `items.append(x)` | Amortized O(1) |
| Append triggering resize | O(N) |
| Insert at index 0 | O(N) |
| Delete from the middle | O(N) |
| Membership search, `x in items` | O(N) |

Insertion and deletion costs depend on position and the need to shift references. Searching a list is generally linear because it may examine elements one by one.

## 6. Why insertion at the beginning costs O(N)

```python
items = ["A", "B", "C", "D"]
items.insert(0, "X")
```

Result:

```python
["X", "A", "B", "C", "D"]
```

Existing references must shift right to preserve order. Spare capacity can avoid a resize, but it does not eliminate the shifting work.

## 7. Aliasing, mutation, and rebinding

### Assignment does not copy a list

```python
a = [10, 20, 30]
b = a

b.append(40)

print(a)  # [10, 20, 30, 40]
print(b)  # [10, 20, 30, 40]
```

Both names refer to the same list object. `append()` mutates that shared object.

### Concatenation creates a new list

```python
a = [10, 20, 30]
b = a

b = b + [40]

print(a)  # [10, 20, 30]
print(b)  # [10, 20, 30, 40]
```

The `+` operation creates a new list and the assignment rebinds `b` to it. The original list referenced by `a` is unchanged. List concatenation copies references and takes O(N) time in the size of the resulting list under the usual model.

### Function parameters and shared objects

```python
def add_item(items):
    items.append(40)

numbers = [10, 20, 30]
add_item(numbers)

print(numbers)  # [10, 20, 30, 40]
```

Python uses object references and call by sharing (also called pass by object sharing). The parameter refers to the same list object, so mutation is visible to the caller.

By contrast:

```python
def change_list(items):
    items = [100, 200]

numbers = [10, 20, 30]
change_list(numbers)

print(numbers)  # [10, 20, 30]
```

Here, the local name `items` is rebound to a new list. The original list is not mutated.

## 8. Object identity: `id()` and `is`

- `id(a)` returns the identity value of the list object `a` refers to.
- `id(a[0])` returns the identity value of the object referenced by the first element.
- `a is b` checks whether both names refer to the same object.
- `a == b` compares list contents for equality.

Two distinct lists can contain references to the same element objects. For example, in typical CPython implementations, small integers such as `10` are cached and reused. Therefore, `id(a[0])` and `id(b[0])` can be equal even when `a` and `b` are different lists. Do not rely on integer identity as a general substitute for value equality; use `==` to compare values.

## AI engineering connection

Python lists are useful for collecting document chunks, API results, and batches of work when order matters and the collection grows dynamically. A set or dictionary may be better for repeated membership checks or key-based lookup. Specialized numerical arrays may be more suitable for large numerical workloads.

## Key takeaways

- A Python list is a dynamic array of object references.
- Index access is O(1).
- Append is amortized O(1), but a resize-triggering append can be O(N).
- Insertion near the beginning or middle can take O(N) due to shifting.
- Assignment creates another reference; it does not automatically copy a list.
- Mutation affects all names referring to the same list object; rebinding a local name does not rebind the caller's name.
- Distinguish object identity (`is`) from value equality (`==`).
