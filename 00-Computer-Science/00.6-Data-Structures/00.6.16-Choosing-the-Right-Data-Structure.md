# Module 00.6.16 --- Choosing the Right Data Structure

## 1. Core principle

There is no universally best data structure. The right choice depends on
the data, the operations performed most often, the access pattern,
ordering and uniqueness requirements, insertion/deletion patterns, time
and memory constraints, and whether the system is in-memory, persistent,
concurrent or distributed.

**Choose a data structure based on the workload, not simply because it
is familiar.**

## 2. Questions to ask before choosing

1.  What kind of data am I storing?
2.  How will I access it: by index, key, priority, relationship or
    prefix?
3.  Does order matter?
4.  Do I need fast membership checks?
5.  Do I need to insert or delete frequently?
6.  Do I need to retrieve the smallest or largest item repeatedly?
7.  Is the data hierarchical or relationship-based?
8.  What are the time and memory constraints?

Start by identifying the most frequent or performance-critical
operation.

## 3. Comparing the major data structures

### Arrays and Python lists

Use an array or Python list when you need ordered elements, fast indexed
access, efficient iteration, and frequent appends at the end.

  Operation                         Typical complexity
  ------------------------------- --------------------
  Access by index                                 O(1)
  Search by value                                 O(n)
  Append at end                         Amortized O(1)
  Insert at beginning or middle                   O(n)
  Delete at beginning or middle                   O(n)

Python lists are dynamic arrays and are a practical default for many
ordered collections.

### Linked lists

Use a linked list when node-based insertion or deletion is important and
you already have the necessary node reference.

  Operation                              Typical complexity
  ------------------------ --------------------------------
  Access by index                                      O(n)
  Search by value                                      O(n)
  Insert at head                                       O(1)
  Delete at a known node     O(1), with required references

A linked list is not automatically faster than a Python list. Finding
the position or node may itself take O(n), and linked lists have pointer
and memory overhead.

### Stacks

A stack follows **LIFO --- Last In, First Out**.

Use it for undo/redo history, function-call tracking, depth-first search
and backtracking.

  Operation     Complexity
  ----------- ------------
  Push                O(1)
  Pop                 O(1)
  Peek                O(1)

``` python
stack = []
stack.append("page-1")  # push
stack.append("page-2")
last_page = stack.pop() # pop: page-2
```

### Queues

A queue follows **FIFO --- First In, First Out**.

Use it for processing jobs in arrival order, background task pipelines,
breadth-first search and producer-consumer workflows.

With a suitable queue implementation, enqueue and dequeue are O(1).

``` python
from collections import deque

jobs = deque()
jobs.append("job-1")       # enqueue
jobs.append("job-2")
next_job = jobs.popleft()  # dequeue: job-1
```

Avoid repeatedly using `list.pop(0)` for a large queue because removing
the first list element requires shifting the remaining elements.

### Priority queues and heaps

Use a priority queue when items must be processed according to priority
rather than arrival order.

  Operation                      Complexity
  ---------------------------- ------------
  Peek at minimum (min-heap)           O(1)
  Insert                           O(log n)
  Extract minimum                  O(log n)

Python's `heapq` implements a min-heap:

``` python
import heapq

tasks = []
heapq.heappush(tasks, (3, "low priority"))
heapq.heappush(tasks, (1, "urgent"))
heapq.heappush(tasks, (2, "normal"))

priority, task = heapq.heappop(tasks)
print(task)  # urgent
```

The smallest priority value is removed first. For a max-priority
interpretation, one common technique is to store negative priorities.

A heap is not a Binary Search Tree. It efficiently exposes the minimum
or maximum, but it does not keep all elements fully sorted.

### Hash tables, dictionaries and sets

A hash table is the underlying concept used by Python dictionaries and
sets.

**Dictionary:** use it for key-value mapping.

``` python
documents = {
    "doc-101": {"title": "Introduction to AI"},
    "doc-102": {"title": "Neural Networks"},
}

metadata = documents["doc-101"]
```

**Set:** use it for uniqueness and membership checks.

``` python
processed_ids = {"doc-101", "doc-102"}

if "doc-101" in processed_ids:
    print("Already processed")
```

Average-case lookup and membership checks are O(1), while worst-case
behaviour can be O(n).

Choose a dictionary when each key maps to a value. Choose a set when you
only need to track unique values or membership.

### Trees and Binary Search Trees

Use a tree for hierarchical data, such as folder structures, categories
and nested document structures.

A Binary Search Tree (BST) is a binary tree with an ordering rule. Under
the common convention, values in the left subtree are smaller and values
in the right subtree are larger.

For a balanced BST, search, insertion and deletion are O(log n). For an
unbalanced BST, these operations can degrade to O(n).

Use a balanced search tree when you need ordered searching or range
queries.

### Graphs

Use a graph when data represents relationships or connections.

Examples include documents connected by citations, users connected by
friendships, concepts connected in a knowledge graph, and services
connected by dependencies.

A graph consists of vertices (nodes) and edges (connections). It may be
directed or undirected, weighted or unweighted.

With an adjacency-list representation, traversing the graph using BFS or
DFS takes O(V + E), where V is the number of vertices and E is the
number of edges.

### Tries

Use a Trie when operations depend on string prefixes, such as
autocomplete, finding titles beginning with a prefix, or prefix-based
search.

For a word or prefix of length L, insertion and prefix traversal are
typically O(L), excluding the cost of collecting all matching results.

A Trie is useful for prefix search; it is not the same as semantic or
vector search.

## 4. Quick selection guide

  Requirement                                Suitable structure
  ------------------------------------------ -----------------------
  Access by numeric index                    Array / Python list
  Ordered, resizable collection              Python list
  Insert/delete at a known node              Linked list
  Last item added must be processed first    Stack
  First item added must be processed first   Queue
  Process by priority                        Priority queue / heap
  Map a key to associated data               Dictionary
  Track unique values or membership          Set
  Represent hierarchy                        Tree
  Ordered search and range queries           Balanced BST
  Repeatedly retrieve minimum or maximum     Heap
  Represent relationships and connections    Graph
  Search strings by prefix                   Trie

## 6. A practical decision process

1.  **Identify the main operation.** Is it lookup, insertion, deletion,
    ordering, priority retrieval, traversal or prefix search?
2.  **Identify the access pattern.** Is access by index, key, priority,
    relationship or prefix?
3.  **Check time complexity.** Focus on operations performed frequently.
4.  **Check memory cost.** Some structures trade additional memory for
    faster operations.
5.  **Consider the environment.** Does the data need to persist, be
    shared between processes, or work across multiple machines?
6.  **Choose and validate.** Test the structure against realistic data
    sizes and workloads.

Do not optimize based only on theoretical complexity. Measure real
workloads when performance matters.

## 7. Important distinctions to remember

-   A Python list is not the same implementation as a linked list.
-   A stack and a queue differ in removal order: LIFO versus FIFO.
-   A dictionary stores key-value pairs; a set stores unique elements.
-   A hash table provides average-case fast lookup, not guaranteed O(1)
    in every case.
-   A heap is not a BST: a heap supports efficient priority retrieval,
    not general sorted lookup.
-   A BST is not guaranteed to be balanced.
-   A tree represents hierarchy; a graph represents general
    relationships.
-   A Trie is designed for prefix operations, not semantic similarity
    search.
-   The right data structure depends on the operations and workload.

## 8. Connection to AI and LLM engineering

These fundamentals appear in practical AI systems:

-   Document ingestion uses lists, dictionaries, sets and queues.
-   Deduplication uses sets or database uniqueness constraints.
-   Task scheduling can use queues and priority queues.
-   Knowledge graphs use graph structures.
-   Autocomplete can use Tries.
-   Retrieval systems use specialized indexes, including vector indexes,
    which are designed for similarity search rather than ordinary
    exact-key lookup.

Understanding the underlying structures helps you reason about
performance, memory usage and system design.

## 9. Final takeaway

There is no single best data structure.

**The best structure is the one that supports the operations your
application performs most often, within its time, memory and system
constraints.**

The objective is not merely to memorize complexity tables. It is to look
at a problem, identify its access patterns and choose a suitable
representation.
