# Module 00.4.07 — Shared State

## What is shared state?
**Shared state** is data or a resource that multiple execution paths can access.

Threads within the same process commonly share:
- Global variables and shared objects.
- Heap-allocated objects, such as lists and dictionaries.
- Process resources, such as open file descriptors.

Each thread still has its own execution state and stack. Not every variable is shared.

## Example
```python
request_count = 0

def handle_request():
    global request_count
    request_count += 1
```
Threads in the same process can access the same global `request_count`.

## Why shared state matters
Sharing data can be useful—for example, multiple requests can reuse a shared cache or configuration. The risk arises when concurrent operations modify shared mutable data without appropriate coordination.

Conceptually, `request_count += 1` involves reading the current value, calculating the incremented value, and writing the result. If operations interleave, two threads may both read `10` and both write `11`. One increment is lost.

This is one possible **race condition**. Whether a particular operation can race depends on the runtime and operation; do not assume every shared access is unsafe or that the GIL makes every multi-step operation safe.

## Threads versus processes
Threads in one process can access the same ordinary in-process objects. Separate processes generally have separate virtual address spaces, so ordinary Python variables are not automatically shared. Processes need explicit shared-memory or inter-process communication mechanisms to exchange data.

## AI engineering connection
An AI service may maintain an in-memory cache of document embeddings. Multiple requests can reuse the cache, but concurrent updates need a deliberate design—for example, suitable locking, thread-safe structures, or a cache/database that handles concurrency.

## Key takeaways
1. Shared state is data accessible to multiple execution paths.
2. Shared state is not automatically a bug.
3. Concurrent modification of shared mutable data can cause correctness problems.
4. Process memory is generally isolated unless explicit sharing or IPC is used.
