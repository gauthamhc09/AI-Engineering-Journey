# Module 00.4.23 — Python Process Pools

## Why use a process pool?
Creating a separate process for every small task can consume resources and add startup/teardown overhead. A process pool provides reusable worker processes that can process many tasks.

For example, an AI pipeline may need to preprocess hundreds of documents. A limited pool can process several documents concurrently without creating a new process for every document.

## Example with `ProcessPoolExecutor`
```python
from concurrent.futures import ProcessPoolExecutor

def square(number):
    return number * number

if __name__ == "__main__":
    with ProcessPoolExecutor(max_workers=3) as pool:
        results = list(pool.map(square, [2, 3, 4, 5, 6]))

    print(results)
```
Output:
```text
[4, 9, 16, 25, 36]
```

## Key concepts
- `ProcessPoolExecutor` manages a pool of worker processes.
- `max_workers=3` configures the pool for up to three worker processes.
- `pool.map(function, inputs)` distributes inputs among workers and yields results in input order.
- The `with` block manages the executor lifecycle and waits for submitted work during normal shutdown.
- The main-module guard is important on platforms that use the `spawn` start method.

## Why a pool can be more efficient
1. **Controlled resource usage:** The number of concurrently executing worker processes is limited.
2. **Process reuse:** A worker can handle many tasks without starting a fresh process each time.
3. **Parallel execution:** CPU-bound tasks can execute on different cores when resources permit.
4. **Less repeated overhead:** Process creation and teardown are not required for every task.

A pool can queue many tasks even if only a few workers execute them at once. With 100 tasks and four workers, up to four tasks execute concurrently in that pool; the rest wait for workers to become available.

## Choosing the pool size
Four workers do not necessarily match the hardware perfectly. A useful configuration depends on CPU core availability, memory, task duration, workload characteristics, and other processes running on the machine. More workers do not always mean better performance.

## AI engineering connection
Process pools can help with CPU-intensive parsing, transformation, or preprocessing. Network-heavy tasks may benefit more from threads or asynchronous I/O, while GPU-heavy inference often needs a different concurrency design.
