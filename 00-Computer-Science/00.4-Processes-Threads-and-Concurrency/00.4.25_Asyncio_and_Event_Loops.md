# Module 00.4.25 — Asyncio and Event Loops

## Why `asyncio` exists
`asyncio` supports concurrent I/O by coordinating asynchronous tasks, often within a single thread. It is useful when many operations spend time waiting and the libraries involved support asynchronous I/O.

For example, an application may need to fetch many documents or call multiple asynchronous APIs without creating a thread for every operation.

## The event-loop model
1. A task runs until it completes or suspends at an asynchronous waiting point.
2. If a task awaits an incomplete operation, it suspends.
3. The event loop can run another ready task on the same thread.
4. When the awaited operation completes, the suspended task can resume.

This is concurrency without requiring one thread per task. The operating system still handles the underlying network and I/O activity.

## Example
```python
import asyncio

async def download_document(name):
    print(f"Starting {name}")
    await asyncio.sleep(2)  # Simulates asynchronous waiting
    print(f"Finished {name}")

async def main():
    await asyncio.gather(
        download_document("A"),
        download_document("B"),
        download_document("C"),
    )

asyncio.run(main())
```

The three simulated waits can overlap, so the total time may be close to two seconds rather than six seconds.

## Key elements
- `async def` defines a coroutine function.
- Calling a coroutine function creates a coroutine object; it does not, by itself, run the coroutine body to completion.
- `await` suspends the current coroutine when its awaited operation is incomplete, allowing the event loop to run other ready tasks.
- `asyncio.gather()` schedules the supplied awaitables to make progress concurrently and waits for their results.
- `asyncio.run()` runs the top-level coroutine using an event loop.

## Async I/O must cooperate
`await` does not magically make a blocking function asynchronous. The awaited operation must cooperate with the async execution model.

For example, `await asyncio.sleep(2)` is non-blocking. Using `time.sleep(2)` inside an async task blocks the event-loop thread, preventing other tasks on that loop from progressing during the sleep.

## Threading versus asyncio
- **Threading:** Multiple threads are scheduled by the operating system; useful for I/O involving blocking APIs or libraries.
- **Asyncio:** A single thread can coordinate many tasks that yield at asynchronous suspension points; useful when the I/O libraries support async operation.
- Neither model automatically makes CPU-bound Python code execute in parallel on multiple cores.

## AI engineering connection
In a FastAPI or LLM application, `asyncio` can help coordinate many concurrent network requests, asynchronous database operations, and external API calls. Use compatible async libraries and avoid blocking the event-loop thread with long synchronous operations.
