# Module 00.4 — Processes, Threads, and Concurrency

# 00.4.02 — CPU Core and Execution

## 1. What is a CPU core?

A CPU core is a hardware execution unit capable of executing machine instructions. For this module's simplified mental model, each core can execute a scheduled thread at a given instant.

A multicore CPU can execute instructions from different threads simultaneously on different cores, subject to hardware, operating-system, and runtime constraints.

## 2. Four threads on two cores

Suppose a process contains four runnable threads: A, B, C, and D. The computer has two CPU cores.

In a simplified model, two threads can execute at the same instant—one per core. The operating system can switch between runnable threads over time so that all four make progress.

```text
Time ───────────────────────────────────────>

Core 1: | Thread A | Thread C | Thread A |
Core 2: | Thread B | Thread D | Thread B |
```

This is an illustrative schedule, not a promise of equal time slices or a fixed order. Real scheduling depends on readiness, blocking, priorities, and OS scheduling decisions.

**Important:** Four runnable threads on two cores cannot all execute simultaneously in this simplified model. However, they can make concurrent progress over time.

## 3. Concurrent progress versus simultaneous execution

- **Concurrent progress:** Multiple tasks make progress during overlapping periods; a single core can switch between tasks.
- **Simultaneous execution / parallel execution:** Multiple tasks execute at the same instant on separate execution resources, such as separate CPU cores.

Do not confuse having many threads with having many cores.

## 4. A blocked thread does not continuously occupy a core

Imagine Thread A sends a database query and must wait for the response, while Thread B is ready to execute CPU instructions.

A typical sequence is:
1. Thread A sends the query.
2. Thread A waits for the response and becomes blocked.
3. While A is blocked, the OS can schedule another runnable thread, such as B, on an available core.
4. When the database response arrives, A becomes runnable again.
5. The scheduler selects a runnable thread when appropriate; A resumes when it receives CPU time.

The database response arriving does not guarantee that Thread A executes immediately. It becomes eligible to run, and the scheduler determines when it receives CPU time.

### Runnable vs blocked

- **Runnable:** A thread is eligible to execute, though it may be waiting for CPU time.
- **Blocked:** A thread is waiting for an event or resource and cannot currently make progress by executing on the CPU.

A blocked thread does not need to occupy a CPU core continuously while it waits.

## 5. Async connection preview

With `asyncio`, a coroutine waiting on a properly asynchronous database operation can yield control to the event loop. Other coroutines can then make progress without needing one OS thread per waiting request.

Async does not automatically speed up CPU-bound work. We will study event loops and coroutines later in the module.

## Key takeaways

- A CPU core is a hardware execution resource.
- Multiple cores can execute different threads simultaneously.
- One core can switch between runnable threads, allowing concurrent progress.
- A blocked thread is waiting and does not continuously occupy a CPU core.
- When a blocked thread becomes runnable, it is not guaranteed to execute immediately.
- The operating system scheduler decides which runnable thread gets CPU time.
- Thread count, core count, and actual parallel execution are different things.
