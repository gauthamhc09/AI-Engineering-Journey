# Module 00.4.11 — Mutex

## What is a mutex?
**Mutex** stands for **mutual exclusion**. A mutex is a synchronization primitive designed to ensure that only one thread at a time can enter a protected critical section.

## Mutex versus lock
- **Lock:** A broad term for a synchronization mechanism that controls access.
- **Mutex:** Emphasizes mutual exclusion—one owner at a time.

In many programming contexts, the terms are used interchangeably. Exact terminology varies by language and operating system. Python's basic `threading.Lock` is not ownership-enforcing; a different thread can release it. Some operating-system mutexes require the owning thread to release them.

## Python example
```python
import threading

cache = {}
mutex = threading.Lock()

def add_document(doc_id, embedding):
    with mutex:
        cache[doc_id] = embedding
```
Threads that use this same lock must take turns executing the protected section. The `with` statement releases the lock when the block exits. Other code that accesses or modifies the dictionary without following the same locking protocol may still introduce concurrency problems.

## Waiting and fairness
When a thread attempts to acquire a held lock, it must wait. Depending on implementation and contention, it may briefly spin or be parked by the runtime/OS; it is not guaranteed to be asleep in every implementation. A lock also does not guarantee which waiting thread acquires it next.

## AI engineering connection
A mutex-style lock can coordinate concurrent cache updates in an AI API. An in-process Python lock cannot coordinate separate worker processes or multiple servers; those require suitable cross-process or distributed coordination.

## Key takeaways
1. A mutex provides mutual exclusion.
2. Lock and mutex are often used interchangeably, depending on context.
3. All relevant code paths must follow the same locking protocol.
4. Lock acquisition does not guarantee immediate execution or fairness.
