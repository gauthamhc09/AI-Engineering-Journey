# Module 00.4.12 — Semaphores

## What is a semaphore?
A **semaphore** is a synchronization primitive that controls how many participants can access a resource or section concurrently. A mutex-style lock generally allows one holder at a time; a semaphore initialized to 3 can allow up to three threads to hold permits concurrently.

## Core operations
- **Acquire:** Take one available permit. If none is available, wait.
- **Release:** Return a permit so another waiting thread can proceed.

If a semaphore starts with three permits and three threads acquire them, a fourth thread must wait until a permit is released.

## Python example
```python
import threading

db_semaphore = threading.Semaphore(3)

def handle_request():
    with db_semaphore:
        perform_database_work()
```
This allows up to three threads to hold permits concurrently. The work should actually use the resource whose concurrency is being limited.

## Typical uses
- Limit concurrent database connections or operations.
- Bound simultaneous requests to a model-serving endpoint.
- Control access to another capacity-constrained resource.

## Mutex versus semaphore
- **Mutex:** Usually provides exclusive access to one thread at a time.
- **Semaphore initialized to N:** Allows up to N permit holders at a time.

A semaphore controls concurrency; it is not automatically a substitute for protecting every shared mutable object. When all permits are taken, another thread waits. A release makes a permit available, but does not guarantee that a particular waiting thread runs immediately.

## Key takeaways
1. A semaphore maintains a permit count.
2. Acquire consumes a permit; release returns one.
3. A semaphore initialized to 3 allows at most three permit holders concurrently.
4. Use it to limit access to finite-capacity resources.
