# Module 00.4.06 — Parallelism

## What is parallelism?
**Parallelism** means two or more computations execute at the same time on separate execution resources, such as CPU cores. It can reduce completion time when work can be performed independently and benefits from multiple cores.

## Threads and CPU cores
- A thread is an execution path; it is not permanently assigned to one CPU core.
- The operating system may move a thread between cores over time.
- A single thread does not execute simultaneously on multiple cores.
- Multiple runnable threads can execute in parallel when suitable CPU cores are available.

## Python and CPU-bound work
In standard GIL-enabled CPython, the Global Interpreter Lock generally prevents multiple threads from executing Python bytecode in parallel within the same interpreter. For CPU-bound Python work, multiple processes can often achieve parallel execution because each process has its own interpreter and GIL. Benefits depend on workload, startup and communication overhead, and available resources.

## Concurrency versus parallelism
- **Concurrency:** Multiple tasks make progress during overlapping periods; execution may be interleaved.
- **Parallelism:** Multiple tasks execute at the same instant on different execution resources.

Concurrency does not require multiple CPU cores. Parallelism requires simultaneous execution on multiple resources.

## AI engineering connection
In an AI pipeline, downloading documents is often I/O-bound and can overlap. CPU-heavy parsing or transformations may benefit from parallel workers if the workload and runtime support it.

## Key takeaways
1. One thread is one execution path, not a worker that uses every core simultaneously.
2. More threads do not automatically mean more parallelism or better performance.
3. Choose tools based on whether work is I/O-bound or CPU-bound, and measure real performance.
