# Module 00.4.18 — Queues

## What is a queue?
A **queue** is an IPC mechanism that lets processes exchange messages or work items through a shared communication channel. Queues commonly use FIFO order: first in, first out.

A producer puts work into the queue, and a consumer retrieves work for processing.

## Producer–consumer example
A FastAPI process may enqueue document jobs while an AI worker retrieves and processes them. This decouples job submission from job execution.

## Python example
```python
from multiprocessing import Process, Queue

def worker(job_queue):
    job = job_queue.get()
    print("Processing:", job)

if __name__ == "__main__":
    job_queue = Queue()
    process = Process(target=worker, args=(job_queue,))
    process.start()
    job_queue.put("Generate embeddings")
    process.join()
```
This simplified worker processes one job and exits.

## Waiting jobs and backpressure
If 10 jobs are placed in a queue and one worker processes one job at a time, the other jobs remain queued until consumers retrieve them, assuming the queue has capacity and no other consumer removes them.

If jobs arrive faster than workers can process them, the queue may grow, increasing memory usage and latency. Bounded queues and backpressure can help control incoming work.

## Production considerations
A production job system may need retries, failure handling, job status, capacity limits, and persistence if jobs must survive process or machine restarts.

## AI engineering connection
Queues can separate request handling from expensive document processing: FastAPI receives a document, submits a job, a worker generates embeddings, and the result is stored or communicated back.

## Key takeaways
1. Queues decouple producers from consumers.
2. Work items wait until a consumer retrieves them.
3. Queue capacity and consumer throughput affect latency and memory use.
4. Production systems need explicit failure and durability decisions.
