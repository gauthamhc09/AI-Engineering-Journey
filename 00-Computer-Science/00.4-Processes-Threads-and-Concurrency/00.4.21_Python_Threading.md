# Module 00.4.21 — Python Threading

## Why threading exists
Threading is useful when a program manages multiple tasks whose progress can overlap, especially I/O-bound tasks such as downloading documents, making network requests, or waiting for blocking APIs. While one thread waits for I/O, another thread may make progress.

## Creating and running a thread
```python
import threading
import time

def download_document(name):
    print(f"Starting {name}")
    time.sleep(2)  # Simulates waiting for I/O
    print(f"Finished {name}")

thread = threading.Thread(
    target=download_document,
    args=("Document A",)
)
thread.start()
thread.join()
print("All work completed")
```

- `threading.Thread(...)` creates a thread object.
- `target` identifies the function the thread should run.
- `args` supplies positional arguments as a tuple.
- `.start()` starts the thread.
- `.join()` makes the calling thread wait until the worker finishes.
- Creating a thread object does not start its work; call `.start()`.

## Main thread and worker thread
```python
thread = threading.Thread(target=download_document, args=("A",))
thread.start()
print("Main thread continues")
```
The main thread does not have to wait for the download to finish before printing. After `start()`, the operating system schedules the main and worker threads independently. The exact output order can vary.

The new thread does **not** necessarily execute on a separate CPU core. Both threads may take turns on one core or be scheduled on different cores. In standard GIL-enabled CPython, Python bytecode execution within one interpreter is generally limited to one thread at a time.

## What `join()` does
- `start()` starts the worker thread.
- `join()` waits for that thread to finish.
- `join()` does not start or stop the worker thread.

## Concurrency with multiple threads
If three document downloads each spend about two seconds waiting for I/O, their waits can overlap. Total time may be closer to two seconds than six seconds, depending on network conditions and overhead. This is concurrency, not proof of CPU parallelism.

## When threading is useful
- I/O-bound tasks
- Network requests and downloads
- Blocking APIs or libraries
- Tasks that spend significant time waiting

For CPU-bound Python bytecode in standard GIL-enabled CPython, threads generally do not provide parallel execution within one interpreter. Multiprocessing may be a better fit for CPU-heavy work. For many concurrent I/O operations, `asyncio` can be effective when libraries support asynchronous I/O.

## AI engineering connection
Threads can help an AI application fetch several documents or call multiple blocking external APIs concurrently. The best approach depends on whether the workload is I/O-bound, CPU-bound, or delegated to native/GPU operations.
