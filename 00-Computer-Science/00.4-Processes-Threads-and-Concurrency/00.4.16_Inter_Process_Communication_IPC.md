# Module 00.4.16 — Inter-Process Communication (IPC)

## What is IPC?
**Inter-Process Communication (IPC)** is a collection of mechanisms that allow separate processes to exchange data and coordinate their activities.

Separate processes generally have independent virtual address spaces. A process cannot automatically read another process's ordinary Python variables just because the variables have the same name.

## Common IPC mechanisms
- **Pipes:** Communication channels through which processes send and receive data.
- **Queues:** Abstractions for exchanging queued messages or work items, often in producer–consumer systems.
- **Shared memory:** A designated memory region that multiple processes can access.
- **Sockets:** Communication endpoints that can connect processes on the same machine or different machines.

## IPC versus shared state
- Threads in one process can access the same ordinary in-process objects.
- Separate processes generally have separate address spaces.
- IPC provides an intentional way for processes to exchange data or coordinate.
- Shared memory is one IPC approach; other mechanisms may transmit messages or copies of data.

## Python example
```python
from multiprocessing import Process, Queue

def ai_worker(queue):
    document = queue.get()
    print("Processing:", document)

if __name__ == "__main__":
    queue = Queue()
    worker = Process(target=ai_worker, args=(queue,))
    worker.start()
    queue.put("Research document")
    worker.join()
```
The parent process sends a document through the queue; the worker receives it through the communication mechanism.

## AI engineering connection
A FastAPI process can send document-processing tasks to a separate worker process. The worker may generate embeddings and communicate results through a queue or another suitable channel.

## Key takeaways
1. Separate processes do not automatically share ordinary Python variables.
2. IPC allows processes to exchange data and coordinate.
3. IPC includes message-based mechanisms and shared memory.
4. Choose a mechanism based on data size, performance, topology, and reliability needs.
