# Module 00.4.10 — Locks

## What is a lock?
A **lock** is a synchronization mechanism that coordinates access to shared state. A thread acquires the lock before entering a protected section and releases it afterward. For a basic exclusive lock, only one thread can hold that lock at a time.

## Python example
```python
import threading

balance = 10_000
lock = threading.Lock()

def withdraw(amount):
    global balance

    with lock:
        if balance >= amount:
            balance -= amount
            return True
        return False
```
The balance check and deduction occur while the lock is held. If two threads each attempt to withdraw `10_000`, one can withdraw successfully; the other waits and then sees the updated balance.

The `with lock:` context-manager form releases the lock when the block exits, including when an exception occurs.

## Important properties
- **Mutual exclusion:** Only one thread can hold a given basic exclusive lock at a time.
- **Coordination:** Other threads attempting to acquire the same lock must wait until it becomes available.
- **Scope matters:** Relevant code paths must use the same lock.
- **Locks have costs:** Excessive locking can reduce concurrency, and incorrect locking can cause deadlocks.

## A lock is not an automatic forcefield
If Thread A acquires a lock but Thread B modifies the same dictionary without acquiring that lock, Thread B does not automatically become protected. A lock coordinates only code that follows the locking protocol.

## Lock versus critical section
- **Critical section:** The code that needs protection.
- **Lock:** A synchronization mechanism used to protect that code.

## AI engineering connection
Locks can protect shared in-memory caches, counters, and other mutable state in threaded AI services. Use them carefully, keep protected sections appropriately scoped, and consider whether a thread-safe data structure or external coordination mechanism is more suitable.

## Key takeaways
1. Acquire the lock before the protected operation.
2. Protect the complete logical operation, including checks and updates.
3. All relevant code paths must follow the same locking protocol.
4. A lock coordinates threads; it does not automatically protect data everywhere.
