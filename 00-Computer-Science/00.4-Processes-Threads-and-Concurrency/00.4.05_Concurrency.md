# 00.4.05 — Concurrency

## Why concurrency matters

A FastAPI RAG service may have one request waiting for PostgreSQL, another waiting for an external LLM API, and another ready to process retrieved chunks. Concurrency lets the service make progress on other tasks while one task is waiting or otherwise not running.

## Definition and mental model

**Concurrency is managing multiple tasks whose execution periods overlap, allowing them to make progress without requiring one task to finish completely before another begins.**

On a single core, a system can interleave execution between tasks. If one task blocks waiting for I/O, another runnable task can use the CPU.

```text
Illustrative timeline; time moves left to right

Task A: | Running |---- Waiting for I/O ----| Resumes |
Task B: |  Ready  |----- Running -----------| Continues |
```

This illustrates overlapping task lifetimes, not simultaneous CPU execution on a single core.

## Concurrency vs. parallelism

- **Concurrency:** Multiple tasks make progress during overlapping periods. Their execution may be interleaved.
- **Parallelism:** Multiple tasks execute at the same instant on separate execution resources.

A system can be concurrent without being parallel. A multicore machine can support parallelism, but multiple cores alone do not guarantee that a program uses them effectively.

## Python approaches

| Approach | Typical use |
|---|---|
| `threading` | Tasks involving blocking I/O, depending on libraries and runtime |
| `multiprocessing` | CPU-intensive work that can benefit from multiple processes |
| `asyncio` | Many I/O-bound tasks using compatible asynchronous APIs |

These are guidelines, not universal rules. The right choice depends on workload, runtime, libraries, communication overhead, and resource limits. Async does not automatically accelerate CPU-heavy computation.

## AI Engineering example: document-processing pipeline

Suppose each of 100 documents needs:
- A download from an external API (about two seconds).
- A CPU-intensive computation (about two seconds).

Downloads can overlap, while CPU computation uses one core.

Concurrency can be useful because:
1. Documents can download concurrently.
2. As each document becomes available, processing can begin.
3. While other documents are downloading, the CPU can process a ready document.
4. This overlaps I/O waiting with CPU work rather than waiting for all downloads to finish first.

The CPU-intensive computations still execute one at a time on a single core in this simplified model. Concurrency overlaps stages; it does not make one core execute multiple computations simultaneously.

If documents arrive faster than the CPU can process them, a queue can grow. Real systems need sensible concurrency limits and backpressure.

## Potential benefits

- **Throughput:** More requests or tasks completed over time.
- **Resource utilization:** Less time wasted while useful work is waiting on I/O.
- **Responsiveness:** One slow I/O operation need not block all other requests.

Concurrency also introduces challenges such as shared-state bugs, resource contention, rate limits, and more complex error handling.

## AI Engineering connection

For a production RAG service, concurrency can allow one request to make progress while another waits on a database or external model API. The design still needs resource limits, careful shared-state handling, and robust error handling.

## Key takeaways

- Concurrency manages overlapping task execution and progress.
- Concurrency does not require simultaneous instruction execution.
- Parallelism means tasks execute at the same time on separate execution resources.
- Concurrency can improve utilization for I/O-bound workloads.
- Async does not automatically speed up CPU-intensive Python work.
- If work arrives faster than it can be processed, queues can grow; limits and backpressure help control resource use.
- Concurrency introduces coordination and reliability challenges.
