# Module 00.4.26 — Coroutines and `await`

## Why coroutines matter
Coroutines let asynchronous computations suspend and resume while preserving their state. They are central to Python's `asyncio` model, where an event loop coordinates many I/O-bound tasks without requiring a separate thread for every task.

## Coroutine function vs coroutine object
```python
async def fetch_document():
    print("Fetching document")
```
- `async def` defines a **coroutine function**.
- Calling `fetch_document()` creates a **coroutine object**.
- Creating the coroutine object does not execute the function body.

```python
coro = fetch_document()
print("Main continues")
```
This prints `Main continues`; `Fetching document` is not printed because the coroutine was created but neither awaited nor scheduled. Python may issue a `RuntimeWarning` when an unawaited coroutine is discarded.

## How a coroutine runs
A coroutine can be executed by awaiting it from another coroutine or scheduled as a task on a running event loop.

```python
import asyncio

async def fetch_document():
    print("Fetching document")

async def main():
    await fetch_document()

asyncio.run(main())
```
Output:
```text
Fetching document
```
An `await` inside `fetch_document` is not required for its body to execute. Awaiting the coroutine is what runs it in this example.

## What `await` does
When a coroutine reaches `await` on an incomplete awaitable operation, it suspends. Control returns to the caller/event loop, which can run other ready tasks. When the awaited operation completes, the coroutine can resume.

```python
import asyncio

async def fetch_document():
    print("Start")
    await asyncio.sleep(2)
    print("Finished")

asyncio.run(fetch_document())
```
`asyncio.sleep(2)` is asynchronous and yields control while waiting. By contrast, `time.sleep(2)` blocks the thread and can stop other tasks on that event loop from progressing.

## Calling vs scheduling
```python
task_a()  # Creates a coroutine object; does not execute or schedule it.
asyncio.create_task(task_a())  # Schedules the coroutine as a task.
```
`asyncio.create_task()` schedules a coroutine to run on the running event loop. It does not guarantee the coroutine begins executing on the exact line where the task is created; the event loop runs it when it gets an opportunity.

Example:
```python
import asyncio

async def task_a():
    print("A started")
    await asyncio.sleep(2)
    print("A finished")

async def main():
    task = asyncio.create_task(task_a())
    print("Main continues")
    await task
    print("Main finished")

asyncio.run(main())
```
A possible output:
```text
Main continues
A started
A finished
Main finished
```
The precise ordering of `Main continues` and `A started` can depend on when the event loop first runs the scheduled task. `await task` makes `main` wait for that task to finish before printing `Main finished`.

## Important distinctions
- `async def` defines a coroutine function.
- Calling the function creates a coroutine object.
- Awaiting the coroutine runs it as part of the current asynchronous flow.
- `asyncio.create_task()` schedules it independently as a task.
- `await` does not create a thread or process.
- `await` does not automatically make blocking code asynchronous; the awaited operation must cooperate with the async model.

## AI engineering connection
In a FastAPI or LLM application, coroutines can coordinate asynchronous document retrieval, database calls, and external API requests. Keep long blocking or CPU-heavy work off the event-loop thread.
