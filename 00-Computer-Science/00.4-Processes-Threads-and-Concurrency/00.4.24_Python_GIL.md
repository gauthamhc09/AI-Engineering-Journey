# Module 00.4.24 — Python GIL

## What is the GIL?
The Global Interpreter Lock (GIL) in standard GIL-enabled CPython generally allows only one thread at a time to execute Python bytecode within a given interpreter. This matters when choosing between threading and multiprocessing for CPU-bound work.

## Threads versus processes
| Approach | Typical behavior for CPU-bound Python bytecode |
|---|---|
| Multiple threads in standard GIL-enabled CPython | Generally cannot execute Python bytecode in parallel within one interpreter |
| Multiple processes | Can execute Python code in parallel across cores, subject to resource availability |

The GIL does not mean threads are useless, and it does not mean threads can never be scheduled on different cores. It limits simultaneous Python-bytecode execution under that interpreter’s GIL.

## Why threads still help with I/O
Network downloads and other blocking I/O tasks spend time waiting. Common blocking I/O operations release the GIL while waiting, allowing other threads to make progress. Exact behavior depends on the operation and implementation.

For example, four downloads that each take about two seconds might finish in close to two seconds when their waits overlap, rather than taking roughly eight seconds sequentially. Actual timing varies with network conditions and overhead.

## Important qualifications
- This behavior applies to standard GIL-enabled CPython.
- Some native libraries release the GIL while doing computational work.
- GPU operations and native-code computation may behave differently from pure Python bytecode.
- Python versions/builds and interpreter implementations can differ; do not assume every Python runtime has the same GIL behavior.

## Practical selection guide
- **I/O-bound work:** Threads or `asyncio` may help.
- **CPU-bound pure-Python work:** Multiprocessing is often worth considering.
- **AI inference or numerical workloads:** Consider native libraries, GPU execution, batching, and the serving architecture; the GIL alone does not determine performance.

## AI engineering connection
When designing a document-processing or LLM application, identify where time is spent—waiting for network/database responses, executing Python code, or running native/GPU operations—before choosing a concurrency model.
