# Module 00.4.17 — Pipes

## What is a pipe?
A **pipe** is an IPC mechanism that provides a communication channel through which one process can send data and another can receive it.

A traditional anonymous OS pipe is generally one-way. Two pipes can provide two-way communication, or another IPC mechanism can be used.

## Python example with multiprocessing.Pipe
```python
from multiprocessing import Process, Pipe

def worker(connection):
    message = connection.recv()
    print("Worker received:", message)
    connection.close()

if __name__ == "__main__":
    parent_conn, child_conn = Pipe()
    process = Process(target=worker, args=(child_conn,))
    process.start()
    parent_conn.send("Process this document")
    parent_conn.close()
    process.join()
```
Python's `multiprocessing.Pipe()` normally creates two connected endpoints. The default connection supports sending and receiving in both directions, so it is more flexible than a traditional one-way OS pipe.

## What is transmitted?
The receiver gets the transmitted message; it does not gain direct access to the sender's original Python variable.

## AI engineering connection
An API process could send a document-processing task to a worker through a pipe. The worker can process the task and send a result back through the connection.

## Pipes versus queues
- **Pipe:** A communication channel between endpoints.
- **Queue:** A convenient abstraction for storing and retrieving work items, often in FIFO order.

## Key takeaways
1. A pipe provides a channel for transmitting data between processes.
2. A traditional anonymous OS pipe is generally one-way.
3. Python's `multiprocessing.Pipe()` provides connected endpoints that normally support two-way communication.
4. Receiving a message is not the same as sharing the sender's ordinary variable.
