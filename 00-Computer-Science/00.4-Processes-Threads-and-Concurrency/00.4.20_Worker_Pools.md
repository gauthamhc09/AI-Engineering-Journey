# Module 00.4.20 — Worker Pools

## What is a worker pool?
A **worker pool** is a collection of reusable workers that process tasks from a shared work source, such as a queue. Instead of creating a new process for every document, an application can start a fixed number of worker processes and reuse them for many documents.

## Why use a worker pool?
- **Reuse:** Avoid repeatedly creating and destroying processes.
- **Controlled concurrency:** Limit how many tasks run at once.
- **Parallel processing:** Multiple processes can process CPU-intensive tasks in parallel when suitable CPU cores are available.
- **Resource management:** Avoid spawning an uncontrolled number of workers.

## Python example
```python
from concurrent.futures import ProcessPoolExecutor

def process_document(document):
    return document.upper()  # Simplified example

if __name__ == "__main__":
    documents = ["document A", "document B", "document C"]
    with ProcessPoolExecutor(max_workers=3) as pool:
        results = list(pool.map(process_document, documents))
    print(results)
```
This distributes tasks across a pool of up to three worker processes. Actual parallelism and performance depend on workload and available resources.

## Why not create one process per document?
Creating 1,000 processes for 1,000 documents can incur substantial process startup, memory, scheduling, and coordination overhead. A small reusable pool limits resource usage and processes jobs over time.

The best pool size depends on workload characteristics, CPU and memory limits, I/O, and task cost.

## AI engineering connection
Worker pools can be useful for CPU-intensive document parsing, preprocessing, and batch tasks. For GPU inference or I/O-heavy work, a different worker model may be more appropriate.

## Key takeaways
1. A worker pool reuses a bounded set of workers.
2. Pools control concurrency and reduce repeated startup overhead.
3. More workers do not always improve performance.
4. Choose pool type and size based on workload, resource limits, and measured behavior.
