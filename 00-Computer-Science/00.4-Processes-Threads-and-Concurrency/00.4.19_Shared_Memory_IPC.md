# Module 00.4.19 — Shared-Memory IPC

## What is shared-memory IPC?
With **shared-memory IPC**, separate processes are allowed to access a designated memory region. This differs from their ordinary, separate virtual address spaces.

Unlike message-based IPC, shared memory does not inherently require every item to be transmitted as a separate message copy. It can be efficient for large amounts of data.

## Why synchronization is still needed
Shared memory provides access to common storage; it does not automatically coordinate how processes read and write it. If Process A updates data while Process B reads it, B might observe incomplete or inconsistent data. Locks, semaphores, or other synchronization mechanisms may be needed.

## Python example
```python
from multiprocessing import shared_memory

shm = shared_memory.SharedMemory(create=True, size=100)

try:
    shm.buf[0] = 42
    print(shm.buf[0])  # 42
finally:
    shm.close()
    shm.unlink()
```
This creates a shared memory block and accesses its first byte. A second process can attach to the same block by name and access the same underlying memory. Ensure all attached processes are finished before unlinking it, and synchronize concurrent access when necessary.

## AI engineering connection
Shared memory can help processes exchange large numerical arrays, image data, or embedding matrices without repeatedly copying all the data through messages.

## Key takeaways
1. Processes can deliberately access the same designated memory region.
2. Shared memory can reduce data-copying overhead for large data.
3. Shared access does not automatically make concurrent reads and writes safe.
4. Coordinate access and manage the shared region's lifecycle carefully.
