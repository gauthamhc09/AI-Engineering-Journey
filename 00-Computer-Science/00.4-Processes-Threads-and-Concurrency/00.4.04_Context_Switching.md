# Module 00.4 — Processes, Threads, and Concurrency

# 00.4.04 — Context Switching

## Definition

A **context switch** occurs when the CPU stops executing one thread and begins executing another, requiring the system to preserve the first thread's relevant execution state and establish the next thread's state.

## Simplified sequence

1. Thread A is running.
2. A switch is triggered, for example by preemption.
3. A's necessary CPU context is saved.
4. B's context is restored.
5. B runs; A can resume when scheduled later.

The context includes the program counter and relevant CPU registers. The thread's stack and other memory generally remain where they are; the system does not copy the entire stack every time a thread is switched out.

## Thread switch vs. process switch

| Aspect | Thread switch within the same process | Switch between processes |
|---|---|---|
| CPU execution state | Must switch | Must switch |
| Address space | Usually the same | Usually different |
| Memory-management changes | Often less work | May require additional work |
| Typical overhead | Often lower | Can be higher |

These are general tendencies, not guarantees. The actual cost depends on the operating system, hardware, and which resources must change.

## Why context switching matters

If an application creates too many threads for tiny tasks, frequent context switches can consume CPU time without doing useful application work. Threads also use memory and scheduling resources. More threads do not automatically improve throughput or latency.

## Context switch vs. mode switch

A **context switch** changes which thread is executing. A **mode switch** changes privilege level, such as moving between user mode and kernel mode; it does not necessarily change the running thread.

## AI Engineering connection

A document-processing service may have many runnable tasks. Context switching helps the OS share CPU time, but excessive switching can add overhead. For production systems, concurrency should be balanced against task size, memory use, throughput, and latency.

## Key takeaways

- A context switch changes the thread executing on the CPU.
- The system preserves the outgoing thread's relevant CPU state and establishes the incoming thread's state.
- The stack and other process memory generally remain in memory.
- Switching between processes can require more work than switching between threads in the same process, though this is not a universal guarantee.
- Context switching has a cost; more threads do not automatically improve performance.
- Context switches and mode switches are different concepts.
