# Module 00.4.09 — Critical Sections

## What is a critical section?
A **critical section** is a portion of a program that accesses shared state and may need protection from conflicting concurrent operations.

## Example: withdrawing from a balance
```python
balance = 100

def withdraw(amount):
    global balance
    if balance >= amount:
        balance -= amount
```
Imagine two threads each try to withdraw `100` from a balance of `100`. Both threads might check the balance before either deduction occurs. Both checks can pass, potentially allowing the balance to become negative.

## Protect the complete logical operation
The critical section may include:
1. Checking whether sufficient balance exists.
2. Deducting the requested amount.
3. Storing the updated balance.

Protecting only `balance -= amount` may be insufficient because both threads could already have passed the balance check.

**Principle:** Protect the complete logical operation that must remain consistent—not merely the line that changes a variable.

## How locks help
A lock can make cooperating threads take turns through the protected section. When one thread holds the lock, another thread attempting to acquire that same lock must wait until it becomes available.

The same lock must be used by every relevant code path; otherwise, the data is not fully protected.

## AI engineering connection
An AI service that checks whether a job is available and then marks it as claimed may need those steps to behave as one coordinated operation, preventing multiple workers from claiming the same job.

## Key takeaways
1. A critical section is code that needs protection from conflicting concurrent access.
2. The protected region may span several statements.
3. Protecting only the final write may not protect earlier checks or assumptions.
4. Locks are one common way to protect critical sections.
